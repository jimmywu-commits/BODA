# 吸底圖便捷編輯器

電商頁面「吸底圖」（底部促銷/導購橫幅，2–5 顆 icon+文字組，依互動狀態切換單顆反白橘/紅色、
其餘灰階）的快速編輯工具，取代過去用 PS 手工對位、調色、逐張輸出的流程。

> 📘 **只是要用這個工具、不改程式的話，請看 [使用說明.md](使用說明.md)。**
> 🏗 **要接手維護、想先看懂整體結構，請看 [架構說明.md](架構說明.md)。**
>
> 這一份是三者裡最細的：每個設計決策的成因、量測數字與取捨都寫在裡面。

## 怎麼打開

直接雙擊 `index.html` 用瀏覽器開啟即可，**不需要安裝任何東西，也不需要架 server**。
編輯、預覽、批次匯出 PNG 全部都能在 `file://` 底下正常運作。

**需要連網**：本工具會從外部載入 Konva（畫布引擎）、JSZip（打包匯出）與
**ShopeeNotoSans 字體 Medium + Bold（約 22MB）**。第一次開啟約需數秒，快取後約 1 秒。
離線時字體無法載入，工具會停在錯誤畫面且不開放匯出（原因見下方「字體」一節）。

## 版面規格（已依 PS 公版數值實作）

```
畫布 1200 x 150 px
├─ 上方 20px：透明像素（匯出的 PNG 這段是透明的，不是白的）
└─ 下方 1200 x 130px：白底，齊下擺放
     ├─ icon 框 107 x 58px，距白底上緣 10px       → y = 30 ~ 88
     ├─ icon 下緣到文字間距 14px                   → 文字帶 y = 102 ~ 130
     └─ 文字下緣距白底下緣 20px                    → 文字帶高度剛好 28px
```

- icon/LOGO **等比例縮放塞進 107x58 框內**（contain，不拉伸變形），再於框內置中。
- icon 與文字各自水平置中，並視為一個整體。
- 每顆依顆數自動等距：中心點 = `1200 × (i + 0.5) / N`。
  最密的 5 顆情況下，中心點間距 240px、扣掉 107px icon 框後仍有 **133px 淨間距**，滿足 >60px。

指定色號：

| 用途 | 色號 |
|------|------|
| 橘色（選取） | `#ee4d2d` |
| 紅色（選取） | `#d0011b` |
| 灰色（未選取） | `#848484` |

文字：**ShopeeNotoSans(content)-Medium、22px、font-weight 500**。
用文字代替 icon 時（9.9 / 10.10）：**Bold、40px、font-weight 700**。

## 字體（重要）

專案指定字體為 **ShopeeNotoSans(content)**，由
[src/render/fontLoader.js](src/render/fontLoader.js) 用 `FontFace` API 從
`https://jimmywu-commits.github.io/shopee/fonts/` 非同步預載。

**載兩個字重**：

| 字重 | 用在哪 | 依規範屬於 | 實際傳輸量（gzip） |
|------|--------|-----------|------------------|
| Medium (500) | 每顆下方那行說明文字 | 主標 | 11.0 MB |
| Bold (700) | 用文字代替 icon 的檔期數字 | 副標 | 11.0 MB |

首次開啟要下載約 **22MB**。CDN 上**沒有 woff2 版本**（`.woff2` / `.woff` / `.otf` 都是 404），
不然體積可以少八成——若之後拿得到 woff2，換掉 `FACES` 裡的檔名就好。

兩個字重放在同一個 `Promise.all`，**任一個失敗都會停在錯誤畫面**。這是刻意的：
「字重不對的圖」和「字體錯的圖」一樣是不能交出去的成品。

### 為什麼載入完成前不畫任何東西

規範鐵律要求「字體 100% 載入成功才能驅動畫布繪製，嚴禁 FOUT 或預設字體替代」。
這不只是美觀問題——實測同一段文字在 Shopee 字體下寬 **189.11px**、系統字體下只有
**172.62px**，**字沒載到就繪製，產出的圖是錯的，而且不一定看得出來**。因此：

- 字體就緒前，畫布**完全不建立**（實測整段載入期間 `Konva.stages.length === 0`），
  不可能出現字體閃爍。
- 字體載入失敗時**不會退回系統字體**，而是顯示錯誤畫面 + 重試按鈕，並且
  `ExportBatch.exportAll()` 會直接擋下匯出並拋錯——寧可不給檔，也不給錯字體的廢圖。

### 為什麼沒有做字體子集化

子集化（只保留常用字，可壓到 1–2MB、可離線）評估後**刻意不做**：吸底圖常出現廠商名稱的
生僻字與特殊符號，一旦不在字集內就會變成空白框或悄悄換字體，**產出壞圖且不易察覺**；
而子集化的主要好處是離線與速度，此專案不需要離線。完整字集零缺字風險，是這裡更重要的取捨。

### 沒有寫後備字體是刻意的

`LAYOUT.fontFamily` 只有 `"ShopeeNotoSansContent"`，沒有 `sans-serif` 後備。
依規範嚴禁預設字體替代，缺字要能被看見，而不是悄悄換成別的字體。

## 配色規則

| 類型 | 選取（反白） | 未選取 |
|------|------------|--------|
| 一般 icon | 圖示與文字都套橘/紅 | 圖示與文字都是灰 `#848484` |
| 廠商 LOGO | **維持原始品牌色**（不套紅/橘），文字套橘/紅 | **單色調置灰**（見下），文字灰 |

顏色**一律由上表的規則決定**，沒有手動改色的入口。這是刻意的：吸底圖的配色屬於品牌規範，
留一個能改成任意色的色票只會讓人不小心產出不合規的圖。要換色請改「反白顏色」的橘/紅切換。

### 廠商 LOGO 的置灰是怎麼做的

「顏色要是 `#848484`」和「要看得出 LOGO 內容」在數學上互斥：純色填滿 `#848484` 每個像素都一樣，
沒有明暗差異就沒有形狀，必然變成一塊灰；標準灰階看得出內容，但灰的深淺由原圖亮度決定，不會是 `#848484`。

因此改用**覆蓋率映射**：把「這個像素離純白多遠」當成墨水覆蓋率，在白與 `#848484` 之間內插。

```
cov  = 這個像素離純白的距離 / 最深的實心像素離純白的距離     (0 = 白, 1 = 最深)
結果 = 白 + (#848484 - 白) x cov
```

一條式子同時給出三個性質，不需要任何門檻或可調參數：

- **最深的地方精確落在 `#848484`**，整顆 LOGO 不會有比規範灰更深的像素。
- **白底 `cov = 0`，自動維持純白**（等同去背），不需要「多白才算白」的門檻。
- **抗鋸齒的過渡像素 `cov` 介於中間，平滑地淡回白色。**

量測只採「實心」像素（`alpha >= 250` 且非白），套用時才涵蓋全部像素。
例外：整顆都是白的 LOGO（白字去背）沒有「離白的距離」可用，退回把所有不透明像素當 `cov = 1`。

### 前一版的兩個 bug（都是實測抓到的）

前一版是把內容的亮度區間 `[minL, maxL]` 壓進 `[base, base x 1.4]`，
並用 `whiteDistance <= 16` 當硬門檻決定「這是白底」。兩個後果：

**1. 邊緣一圈實色灰（使用者回報的「灰階的部分有一圈糊的」）**

離白 17~123 之間的像素 —— 也就是每個筆畫外圈的抗鋸齒 —— 全部被壓進 `[132, 185]`，
再上去直接跳到 255。實測灰階直方圖：

```
修正前   128:1126  144:131  160:135  176:100  192:13   [204~248 全空]  256:4059
修正後   128:1109  144: 68  160: 71  176:100  192:28  208:32  224:50  240:61  256:4045
```

`192` 與 `256` 之間整段是空的——本該平滑淡出的外框，變成一圈約 `#b9b9b9` 的實色鑲邊。

**2. 去背 LOGO 的主體漂色**

半透明邊緣經 `getImageData` 取回的是未預乘的 RGB，低 alpha 時數值本來就有雜訊。
那些雜訊參與了 min/max 量測，主體就不再錨在 `#848484`——
實測一顆單色 `#4a4a4a` 的去背 LOGO 跑出 **`#acacac`**（修正後 `#848484`）。

### 實測結果

| 輸入 | 輸出 |
|------|------|
| 純黑、已去背（透明底） | `#848484` |
| 單色 `#4a4a4a`、已去背 | **精確 `#848484`**（修正前是 `#acacac`） |
| 黑 LOGO + 白底（沒去背） | 白→`#ffffff`、黑→**`#848484`**，中間是連續的灰階 |
| 全白 LOGO（白字去背） | 整顆 `#848484`（否則會整張消失） |

跨過 LOGO 左邊緣的像素剖面（R 通道）：

```
修正前   255 255 255 255 149 132 132 ...      <- 一步到底，外圈另有實色鑲邊
修正後   255 255 255 254 167 132 132 ...      <- 連續，且直方圖不再斷層
```

## 文字字數限制

上限 **5 字**，中文（全形）算 1 字、英文/數字/符號（半形）算 0.5 字。
這是**軟性警告，不是硬性阻擋**。超過仍然打得進去、畫布也照畫、匯出也照匯，
只是會有三層越來越明顯的提示：

| 狀態 | 計數器 | 輸入框 | 匯出區 |
|------|--------|--------|--------|
| 未達上限 | 灰色 `3/5` | 一般 | — |
| 剛好 5 字 | **橘色** `5/5` | 一般 | — |
| **超過** | **紅色** `7/5` | **紅框 + 紅光暈** | **⚠ 第 N 格超過 5 字，仍會照原樣匯出** |

> 「剛好用滿」是橘色、「已經超了」是紅色，兩者刻意分開——長得一樣就等於沒提示。

紅框的 CSS 用了 `!important`，因為 `:hover` / `:focus` 也會設 `border-color`；
不蓋掉的話滑鼠移過去或點進去編輯時紅框就消失了，而那正是最需要看到它的時候。

匯出區的提醒是必要的：捲到面板底部要按匯出時，上面的紅框早就看不到了。

例：「VIP獨享8折券」依這個規則算 **6 字**（VIP=1.5、獨享=2、8=0.5、折券=2），會轉紅但仍可使用。
從工單匯入時，超過的欄位會在明細裡列出「第幾條第幾格、原文、實際字數」。

### 畫布上怎麼呈現超字

文字**單行往左右溢出**，逼近甚至碰到隔壁格——那正是「超字了」該有的樣子。
不縮小字級、不加省略號，因為那樣會讓超字這件事在畫布上看不出來。

> **維護警告：Konva 的 `Text` 不能同時給固定 `width` 又指望它完整畫出長文字。**
> - 預設 `wrap: "word"` 會換行，第二行會撐出垂直置中的固定高度框、往上撞到 icon。
> - 改成 `wrap: "none"` 但仍給固定 `width` 的話，Konva 會把超出寬度的字**直接切掉**
>   ——實測 14 字的文案只量到 176px（剛好塞進 180px 的框），字是被無聲砍掉的，
>   畫面看起來沒超字但實際少了字，比換行更糟。
>
> 所以 `canvas.js` 的文字節點**刻意不設 `width`**（Konva 視為 auto，不換行也不切字），
> 改成建立後用 `textNode.x(centerX - textNode.width() / 2)` 自己算置中。
> 實測 14 字文案：渲染字串與輸入**完全相同**、單行、寬 308px、
> 以該格中心 600 對稱溢出（span 446–753），且未侵入 icon 區。

## 基本操作

0. **分頁（多條吸底圖）**：畫面最上方的**滿版橫 Bar**，瀏覽器風格頁籤。
   一份工單可能要做好幾條吸底圖，每條各自有自己的顆數、反白顏色、文案與 icon；
   **素材庫跨分頁共用**。頁籤上顯示「吸底 N · 顆數 · 第一格文案」，
   `＋` 新增、頁籤上的 `×` 刪除（刪錯可 Ctrl+Z），至少保留一個分頁。
   Bar 右側是 **↩ 復原 / ↪ 重做**——它們是跨分頁的全域操作，放在這裡比塞進某一條的面板合理。

   > 深色主題下「作用中的頁籤比較亮」本身很微弱（實測底色對比只有 1.28:1），
   > 所以作用中的頁籤另外加了**頂部 3px 品牌色條**、粗體白字、以及多 2px 的高度。
   > 真正讓人一眼認出來的是那條橘線，不是亮度差。
0.5 **開場對話框**：字體閘門通過後自動彈出，問「這次的工單」——見下方「開場對話框」。
1. **📋 匯入工單（xlsx / csv）**：唯一的內容匯入入口，見下一節。
2. **📂 載入進度存檔**：把之前匯出 zip 裡的 `進度存檔.json` 丟回來，接續編輯（見下節）。
3. **反白顏色**：這次活動要用橘還是紅（每條分頁各自獨立）。
4. **模板顆數**：2/3/4/5 顆。
5. **畫質**：補銳化開關（全部分頁共用），**預設開啟**，見「補銳化」。
6. **每顆內容卡**：設為反白 / **點縮圖按鈕開圖像化素材選單**（可搜尋）/ **⬆ 上傳自己的圖** /
   **✏ 編輯（裁切、加透明邊、去背）** / 打文字（含字數）/ **⧉ 這格套到其他分頁**。
   位置一律由模板決定，**沒有**手動拖曳微調（見「畫布縮放與檢視」）。
   畫布可以 **Alt + 滾輪縮放、拖曳平移**，見「畫布縮放與檢視」。
7. **套用到其他分頁**（排在**最後一格下面**）：把這條的 icon 整組推到其他分頁，
   **不動文案**。放在最後而不是最前面，是因為它的前提是「這一條已經全部選好了」，
   而且選完最後一格時視線本來就在面板底部。見下節。
8. **批次匯出**（釘在面板底部，不用捲動）：
   - **匯出目前分頁** — 這條有幾顆就產生幾張 PNG，每張各反白一顆、其餘灰階。
   - **匯出全部分頁** — 只有多於一條時才出現，zip 內依分頁分資料夾。
   - 兩者都會**外加一份 `進度存檔.json`**（一律含全部分頁，即使這次只匯一條）。

## 跨分頁套用 icon

一份工單常常出好幾條吸底圖，icon 幾乎一樣、只差一兩顆，但每一條的文案各自不同。
所以提供兩顆按鈕（只有兩條以上才出現）：

| 動作 | Action | 面板位置 | 範圍 |
|------|--------|---------|------|
| ⧉ 把這條的 icon 全部套到其他 N 條 | `COPY_ICONS_TO_ALL` | 最後一格卡片**下面** | 目前分頁的每一格 → 其他分頁的同一格 |
| ⧉ 這格套到其他分頁 | `COPY_SLOT_ICON_TO_ALL` | 每張卡片右下角 | 只有指定的那一格 |

「整組套用」刻意排在**所有格子後面**：它的前提是「這一條已經全部選好了」。
排在前面等於在還沒選圖時就先問要不要套用，而且使用者選完最後一格時視線已經在面板底部。

搬的是 `iconFieldsOf(slot)` = **`iconId` + `type` + `iconText`** 三個欄位。
`type` 一定要跟著搬，否則廠商 LOGO 到了別頁會被當成一般 icon 染成橘/灰。
**`slot.text` 不在裡面**——跨分頁套用 icon 的前提就是文案各自不同，碰它等於把匯入的結果洗掉。

兩個刻意的取捨（都寫在 `reducers.js` 的註解裡）：

- **來源是空的也照搬**，等於把對方那一格清空。語意是「讓其他頁跟這頁一樣」，
  不是「把有值的補過去」。規則單純、結果可預期，錯了就是一次 Ctrl+Z。
  若改成跳過空格，使用者就沒有辦法用這顆按鈕清掉多餘的 icon。
- **不動顆數。** 對方比較少格就只套得到的部分（按鈕的訊息會講少套了幾格）。
  順手改顆數會連帶改版面，那應該由「模板顆數」自己決定。

> 手動改過某一格之後若要再同步，用**單格**那顆。再按一次整組會把手動改過的其他格蓋掉。

## 畫布縮放與檢視

右下角的縮放列，或直接用滑鼠：

| 操作 | 動作 |
|------|------|
| **Alt + 滾輪** | 以**游標位置為錨點**縮放（和 PS 一致），25% ~ 800% |
| 滾輪 | 平移畫布（這個工作區本來就不捲動，不接手的話單獨滾輪什麼都不會發生） |
| 拖曳畫布（任何位置） | 平移畫布 |
| `100%` | 1 畫布像素 = 1 螢幕像素，用來確認交出去的成品實際長怎樣 |
| `符合視窗` | 整張縮到看得完 |

**縮放只影響檢視，匯出永遠是 1200×150。**

兩個實作上不能改的地方：

- **必須縮放 Konva 的 Stage，不能對容器下 CSS transform。** CSS transform 放大的是「已經畫好的那張
  1200×150 點陣圖」，越放大越糊；縮放 Stage 才會讓文字（向量）與圖片以放大後的尺寸重新繪製。
- **畫布範圍的外框線畫在 Konva 場景裡，不能用 CSS box-shadow。** stage 現在等於整個檢視區而不是
  1200×150，框在容器上會變成框住整個工作區，而且不會跟著縮放平移。見 `canvas.js` 的 `drawArtboard()`，
  它只在預覽畫、`strokeScaleEnabled: false`（放大到 800% 才不會變成一條粗黑帶）。

## icon 的銳利度

### 為什麼只有「上傳的」看起來糊

真正的成因是**降取樣**，不是濾鏡。

內建 `img/` 的素材原始尺寸是 54~70px，本來就接近 107×58 的框，幾乎不需要縮小。
上傳的廠商 LOGO 動輒 600×300，塞進框裡等於**一步縮掉 5~6 倍**——而 canvas 的
`drawImage` 只取 2×2 鄰域做雙線性，縮這麼多會直接跳過大部分來源像素。
結果是**混疊（鋸齒）不是模糊**：細筆畫斷斷續續，LOGO 上的英文小字會直接爛掉。

修正是把降取樣從瀏覽器手上拿回來：`IconImageCache.getScaled()` 用**漸進減半**
（每步最多砍一半，雙線性在 2 倍以內是夠的），縮好之後才交給 Konva。

實測（600×300 測試 LOGO，匯出後對照精確的面積平均，0~255 尺度）：

| | RMS | 平均梯度（理想 14.05） |
|---|---|---|
| 一步 `drawImage`（修正前） | 27.32 | 15.35 |
| 漸進減半（修正後） | **7.95** | 11.97 |

> **`imageSmoothingQuality = "high"` 救不了這件事。** 在單獨的 canvas 上它確實有效
> （RMS 27.3 → 7.8），但實測把它強加到 Konva 建立的每一張畫布上，
> 匯出的無濾鏡 LOGO 完全沒有變化（27.32 → 27.32）。所以只能自己縮。

### 輸出倍率：三者必須對齊

降取樣只做一次才有意義。所以「來源圖縮到幾像素」「濾鏡快取的解析度」「節點在場景裡的尺寸」
三個數字綁在同一個倍率上（`canvas.js` 的 `outputRatio`）：

```js
outputRatio = 匯出 ? 1
                   : min(8, 2^ceil(log2(max(1, 目前縮放))) × devicePixelRatio)
```

- **匯出固定 1。** 匯出走 `stage.toDataURL({ pixelRatio: 1 })`，1200×150 就是最終像素。
  先前這裡是 `× 3` 超取樣，對匯出反而有害——3 倍快取再被一步縮回 1 倍，
  等於多吃一次低品質重新取樣。
- **預覽量化成 2 的次方**，否則滾輪每動一格都會生一份新尺寸的降取樣點陣圖。
  量化值一定 ≥ 實際顯示倍率，Konva 只會小幅縮小。
- **縮放停止 140ms 後整層重畫**（`viewport.js` 的 `scheduleResettle`），不能只重做濾鏡快取——
  來源圖本身是依倍率縮好的，只重做快取會把小圖放大，反而更糊。
- `fitIntoBox()` 的座標與尺寸**一律取整數**。置中算出來是 `centerX - w/2` 這種小數，
  落在半像素上一定會被再取樣一次；匯出倍率是 1，取整之後場景座標就等於 PNG 像素座標。
  代價是長寬比最多變 0.5px（107 上是 0.5%），換到像素對齊很划算。

### 補銳化（預設開啟）

面板「畫質」區可開關，開了會**同時影響預覽與匯出**（走同一個 `viewState`，不會有兩套結果），
並存進進度存檔（不然載回來的圖跟當初交出去的不一樣）。

**同時作用在 icon 與文字上。** 文字那一段是後來才補的，理由見下一節。

實作是標準的 unsharp mask（`colorTheme.js` 的 `createSharpenFilter`），兩個關鍵：

1. **模糊半徑必須跟著快取倍率放大。** 在 3 倍快取上用半徑 1，等於在輸出解析度上用半徑 1/3，
   縮回 1200×150 時整個被平均掉——量起來會像什麼都沒做。
   （匯出的倍率現在是 1，半徑就是 1，剛好等於在輸出解析度上銳化。
   實測匯出的平均梯度 2.84 → 3.30，+16%。）
2. **alpha 也要銳化。** 單色覆蓋過的 icon 每個不透明像素 RGB 完全相同，形狀全部存在 alpha 通道，
   只銳化 RGB 對它一點作用都沒有。文字同理——字形完全是 alpha 覆蓋率，
   所以同一支濾鏡直接就套得上，不需要為文字另外寫一套。

實測（匯出的 1200×150，說明文字區的「中間調像素比例」，越低越銳利）：

| | 中間調比例 | 暗側溢出 |
|---|---|---|
| 關閉 | 0.510 | 0 |
| 開啟 | **0.426**（-16.5%） | 0 |

#### 為什麼從「預設關閉」改成「預設開啟」

先前預設關閉，理由寫的是「實測會吃掉低對比細節」。**那個現象的成因其實是舊的灰階映射**——
它把 LOGO 壓進 `[132, 185]` 這段只有 53 階的窄區間，任何銳化當然都會把細節磨掉。
改成覆蓋率映射（跨滿 `[132, 255]`）之後重量一次：

```
低對比條紋的振幅   關閉 17.81  →  開啟 19.00
```

銳化反而是**放大**低對比細節，不是吃掉。原本的顧慮不再成立，所以改成預設開啟。

**仍然存在的副作用**：unsharp mask 會在邊緣製造暗側溢出。灰階 LOGO 的邊緣實測會出現
`#6f6f6f` 附近的像素（約佔主體的 11%），**比規範的 `#848484` 深**。
這是銳化的本質，PS 的銳利化也一樣。介意的話關掉開關即可。

### 為什麼文字也需要銳化（canvas 沒有 hinting）

canvas 的 `fillText` 是**無 hinting 的灰階 AA**：字形輪廓覆蓋到多少就給多少灰。
Photoshop 的文字消除鋸齒（銳利／明晰）會把筆畫**吸附到像素格線**上，
所以同樣 22px 的中文，PS 出來的橫筆是乾淨的 1px，canvas 是跨兩列的 1.4px 灰帶。
**這是兩個光柵化器的差異，canvas 沒有任何 API 可以要求 hinting。**

排除掉的其他可能（都實測過）：

| 猜測 | 實測 |
|------|------|
| 下載的 PNG 被壓縮了 | 8-bit RGBA 無損 PNG，整張只有 **299 色**、14.9 KB。有損壓縮會有數千色與振鈴 |
| 螢幕縮放影響匯出 | dpr 1 / 1.25 / 1.5 / 2 四種設定下，匯出的 base64 **位元組完全相同** |
| 匯出流程比直接畫還差 | 匯出的「免運費」像素 vs 同字體同字級直接 `fillText`：**RMS 0，最大單通道差 0** |
| 文字被畫在半個像素上 | 中文是全形（1em），字寬永遠是 22 的整數倍，置中後 x 本來就是整數。實測 0.0% 差異 |

唯一有小幅收穫的是**數字與英文**：`"10.10"` 量到 104.44px，置中後 x = 147.78。
取整之後中間調比例 0.272 → 0.255（**-6.3%**）。已經改成一律取整。

剩下的就只有銳化。

### 這件事的物理上限

輸出是 1200×150、icon 框是 107×58，那顆 icon 就只有 58px 高。
上面兩項處理的是「不必要的額外損失」，**沒有辦法在 58 個像素裡放進 58 個像素裝不下的細節**。
覺得成品細節不夠時，正確的作法是換一張構圖更簡單的素材，而不是繼續加後製。

順帶排除掉的兩個猜測（都實測過，都不是原因）：

| 猜測 | 實測 |
|------|------|
| 預覽被 CSS 縮小 | 檢視區 1:1，沒有 CSS 縮放 |
| SVG 用 viewBox 尺寸光柵化再放大 | 48px / 58px / 174px 光柵化銳利度**完全相同**，Chrome 會依繪製尺寸重新光柵化 |

### 一次量錯的紀錄（別再犯）

這份文件前一版寫著「大點陣圖一次降到 58px：`low` / `high` / 逐次減半三者差異在 3% 以內」，
據此判定降取樣不是問題——**那個結論是錯的，而且錯在量測方法**。

當時用的指標是「邊緣梯度」，把梯度高當成銳利。但混疊會**拉高**梯度：
一步 `drawImage` 的平均梯度是 15.35，比理想的面積平均（14.05）還高 9%，
漸進減半反而是 11.97。用梯度當指標，會把壞掉的那個評成最銳利的。

正確的做法是拿**理想的面積平均當參考、量 RMS 誤差**，差距立刻現形（27.32 對 7.95）。
只要是判斷「重新取樣有沒有損失」，就必須對照參考值，不能量單張影像的自身統計量。

## 開場對話框

一進來（或 F5 之後）先彈一次，把「上傳工單」提到預設路徑上：面板上那顆按鈕排在
右側最上方，但新手第一眼看到的是畫布與一堆欄位，很容易就開始一格一格手動打字。

三個實作上的決定：

- **不自己解析檔案。** `PanelUI.mount()` 回傳 `{ importWorkOrder, loadProject }`，
  對話框只負責選檔與顯示錯誤。若讓它自己去呼叫 `WorkOrderImporter`，就會有兩份
  「解析完之後要做什麼」的邏輯，而其中一份不會更新 `ui.importMessage` /
  `importDetail`——從對話框匯入就**看不到那份逐項核對清單**，而那正是匯入最需要的東西。
- **失敗不關閉。** 成功才關，失敗把訊息留在卡片上。一律關閉的話，使用者只會看到
  對話框消失、畫面沒變，分不出是自己選錯檔還是工具壞了。
- **不自己預載字體。** `app.js` 在字體閘門通過、面板掛好之後才呼叫
  `StartupDialog.mount()`，所以走到那裡字體必定 100% 就緒，不需要像蝦導播那支
  `workorder-popup-plugin.js` 那樣自己再載一次並和逾時賽跑。

「已顯示」只記在記憶體，不進 localStorage：F5 就是新的一頁，重新整理多半就是想重來。

> **維護提醒**：它是 modal，會蓋住畫布。任何自動化測試在操作畫布前要先
> `window.StartupDialog.close()`。

## 從工單匯入（xlsx / csv）

按 **「📋 匯入工單」**，選整份工單檔，工具會自動找出裡面的吸底圖區塊、
**每一組各建成一個分頁**，並帶入文案、icon/LOGO 的判定與名稱比對。

支援 `.xlsx` / `.xlsm` / `.csv`（CSV 會以 UTF-8 讀取；xlsx 是二進位，沒有編碼問題）。
試算表解析用 SheetJS，跟 Konva/JSZip 一樣**用到才從 CDN 載入**。

### 為什麼不能寫死座標

工單範例裡吸底圖那一區，五格的**起始欄是 2, 6, 10, 15, 19 —— 寬度 4, 4, 5, 4, 5，不固定**
（合併儲存格造成的）。任何「固定欄距」的寫法從第 3 格就會錯位。列號同理，工單一改版就位移。
所以位置**全部是算出來的，不是查表來的**。

### 定位策略：多重訊號

主結構錨點是「**同一列出現 2 個以上的 `Icon：`**」——這是結構特徵，工單內容再怎麼換都在。
找到之後用其他訊號互相佐證並累計信心分數：

| 訊號 | 分數 | 為什麼可靠 |
|------|------|-----------|
| 有 ≥2 個 `Icon：`（必要） | 3 | 主結構錨點 |
| 找得到文案列（**必要**） | 3 | 找不到就放棄——匯入一整排空文案比沒匯到更糟，它看起來像成功了 |
| A/B 欄含「吸底」 | +5 | 主標籤 |
| 同列含 `Nav.bar` | +4 | **純 ASCII**，編碼、字型、繁簡都不影響 |
| 有 `LOGO：` 列 | +3 | 結構特徵 |
| 有磁碟路徑列（`X:\`） | +2 | 結構特徵 |

**門檻 8** 的意思是：光有「`Icon：` + 文案列」（3+3=6）不夠，一定要**再有至少一個獨立佐證**。
兩個以上互相獨立的結構訊號才算數，單一巧合不會通過。

### 欄位怎麼切

每一格的欄位範圍由 `Icon：` 的**實際欄號**推導：第 k 格 = `[iconCols[k] - 1, iconCols[k+1] - 2]`
（`Icon：` 左邊那一欄是 TRUE/FALSE 勾選欄，也是文案欄）。
用範例工單驗證：`iconCols = [3,7,11,16,20]` → 格子範圍 `[2-5][6-9][10-14][15-18][19-]`，完全吻合。

最後一格**刻意不吃到列尾**——工單右側常有「視覺參考 / 指定」之類的無關欄位，
全吃進來會把那些內容誤判成文案。改成用前面幾格的最大寬度當上限。

**文案列不能靠內容比對**：範例工單裡是「文案05字內」，真實工單裡那格是實際文案。
所以定位方式是「區塊內排除掉 `Icon：` 列、`LOGO：` 列、路徑列之後剩下的那一列」。

### 帶進來什麼

| 工單欄位 | 對應到 |
|---------|--------|
| 文案 | 該格的文字（套用 5 字上限，超過會截斷並在明細裡講明是第幾條第幾格） |
| LOGO 列的 TRUE/FALSE | 該格的 `type` — 勾了就是廠商 LOGO（不套橘/紅，只返灰） |
| `Icon：xxx` / `LOGO：xxx` | 拿去比對素材庫，由嚴到寬：同型別完全相同 → 完全相同 → 同型別包含 → 包含 |

**對不上的名稱一律留空並列出來**，不硬塞一個看起來像的。素材路徑（`G:\共用雲端硬碟`）
無法自動載入——瀏覽器沒有讀取本機路徑的權限，這是安全限制不是實作偷懶。

尾端整格空白（沒文案、沒 icon 名、沒 LOGO 名）會自動砍掉，工單常留著沒用到的格子。

### 不誤植的防線

匯入完會逐條列出**在哪個工作表的第幾列、幾格、每格的文案**，以及所有沒對上的項目——
匯入不能只說「成功」，要能核對。整份匯入是**單一步 undo**，按錯 `Ctrl+Z` 就整個退回。

明細**預設收合**成一行「▸ 匯入明細（N 項）」，需要核對才點開（實測收合可省下 220px 版面）。
用原生 `<details>` 而不是自己做開合，開合狀態由瀏覽器管，面板重繪也不會意外展開。

找不到任何區塊時會明確報錯並說明偵測方式，不會猜一個最像的塞給你。

實測：一份含 3 個工作表的工單（正常區塊 ×2、A 欄沒標籤且無 Nav.bar 又缺路徑列的「變形版」×1、
以及一張純預算表），正確找出 3 組、預算表 0 組；只有 1 個 `Icon：` 的假資料也是 0 組。

### 空欄位的預覽假字

還沒輸入時，畫布上會出現半透明的 **「文字5字內」** 與 icon 框裡的 **「未選圖」**，
讓你先看到版面長相。「文字5字內」依規則剛好 4.5 字，正好示範上限寬度不會超框。

**這些假字只存在畫面預覽，匯出的 PNG 絕對不會有。** 實作上是 `render()` 的 `isPreview` 參數：
畫面 stage 傳 `true`，`exportBatch` 的離屏 stage 不傳。連空 icon 的虛線提示框也一樣是預覽限定，
匯出時完全不畫（實測：全空欄位匯出的 PNG，白底區非白像素數 = **0**）。

> 維護注意：之後若在 `render()` 加新的提示性繪製，記得一併掛在 `isPreview` 底下，
> 否則會直接混進正式輸出的圖素。

## 進度存檔（JSON）

每次匯出的 zip 裡都會附一份 `進度存檔.json`，用面板上的「📂 載入進度存檔」丟回來就能接續編輯。

存的內容：**全部分頁**的顆數、反白欄位、橘/紅、每欄的文字 / iconId / iconText，
以及**你自己上傳的 icon 圖檔本身（base64 內嵌）**。

> 存檔格式 v2 是多分頁結構。**v1（單條）的舊存檔仍然讀得進來**，會自動包成單一分頁。
>
> 舊存檔可能帶著 `offset`（拖曳微調過的位置）。拖曳功能已移除，載入時**刻意不還原**這個欄位——
> 還原了就會出現一個偏掉、卻沒有任何方法歸位的格子。

內嵌圖檔是刻意的取捨：上傳的圖**只活在這次編輯**（重新整理就沒了），存檔若只記 `iconId`，
換一台電腦或重新整理再打開就會全部指向不存在的 icon，變成一排空框。
代價是 JSON 從幾 KB 變成數百 KB——換來的是這份存檔真的能完整還原。
`img/` 來的素材不內嵌、只記 id，因為它們本來就在 git 版控裡人人都有。

載入走的是既有的 dispatch，不繞過 reducer，所以字數上限、顆數範圍、反白索引邊界的防呆都會一併生效。
若存檔裡有目前資料庫沒有的 icon，該欄會留空並在訊息裡明講是第幾欄，不會默默吃掉。

## Icon 資料庫

**唯一的正式來源是 [img/](img/) 資料夾。** 打開工具看到的素材就是那個資料夾的內容，
不多也不少——沒有「只有我電腦上有」的隱藏素材。

### 新增或替換素材（正式作法）

```
1. 把 PNG / JPG / SVG 丟進 img/
2. node tools/build-icon-manifest.js
3. git commit（img/ 與 src/icons/manifest.js 兩個都要）
```

`src/icons/manifest.js` 是**產生出來的，不要手改**——下次重跑會被蓋掉。

**id 由檔名決定，不是由排序決定。** 這點很重要：進度存檔記的是 `iconId`，
若 id 是 `icon-1`／`icon-2` 這種流水號，之後在 `img/` 多放一張圖、排序一變，
所有舊存檔就會靜默指到別張圖。所以 `主會場.png` 的 id 就是 `主會場`，
中日文字元原樣保留，只有空白與標點會換成 `-`。**改檔名等同換一顆新素材**，舊存檔會找不到它。

### 為什麼要多這一道產生步驟，不能直接寫 `img/fire.png`

因為這個工具要能在 `file://` 下雙擊開啟。在 `file://` 把相對路徑的圖畫進 canvas 會讓 canvas
變成 tainted，之後 `toDataURL()` 直接丟 `SecurityError`——**匯出整個壞掉，而且是在按下匯出
那一刻才爆**，不是載入時。所以圖必須以 data URI 內嵌。20 張 PNG 原始 78KB，產出的 manifest 是 107KB。

### 圖像化選單

每一格的素材欄是一顆**顯示縮圖 + 名稱**的按鈕，點下去開浮動選單：縮圖網格 + 搜尋 + 清除。

- 縮圖畫在**淺色底**上。素材是橘色 + 透明鏤空，放在深色面板上鏤空處會糊成一片；
  淺底才和最終輸出的白色區塊一致，看到的形狀就是實際會印出來的形狀。
- 縮圖用**素材原始外觀**，不套配色濾鏡。套色後全部變成同一個橘，反而更難分辨。
- 名稱一定保留：縮圖只解決「這是哪張圖」，但工單匯入比對用的是名稱。
- 選單是 `position: fixed` 掛在 `body` 上的，不是塞進卡片裡——側邊面板有 `overflow: auto`，
  塞在裡面會被裁掉。位置由 JS 依按鈕算，所以**捲動、改變視窗大小、面板重繪時一律關閉**
  （算好的位置會失效，留著就會浮在原地指向已經不存在的按鈕）。
- **「捲動就關閉」不包含選單自己的捲動。** `scroll` 不冒泡，必須用捕獲階段才收得到
  側邊面板內部的捲動，而捕獲階段連 `.icon-grid` 自己的捲動也一起收到。
  早期版本沒有排除，結果是**選單一滾就消失**——素材少時網格不溢出所以看不出來，
  加到 23 個之後選單整個捲不動，下半部的素材永遠選不到。
  現在 `onScroll` 會先 `if (panel.contains(e.target)) return`。詳見「架構說明.md」。

### 臨時上傳（只活在這次編輯）

每一格旁邊的 **「⬆ 上傳」** → 選檔 → 填名稱 → 按 **「加為一般 icon」**（橘）或
**「加為廠商 LOGO」**（灰）。按下去就同時加進素材庫並套用到這一顆；不想留就按「取消」。
按錯型別直接 **Ctrl+Z**，加素材與套用是同一步 undo。

型別按鈕的底色刻意等於該型別實際會渲染成的顏色系（橘＝會套橘/紅，灰＝永遠只有灰）。
灰鈕用的是比規範灰 `#848484` 更深的 `#5a5a5a`——`#848484` 的亮度和品牌橘幾乎相同
（亮度比 1.02:1），並排時只剩色相在區分，對色弱使用者等於沒有區隔。

> **上傳的圖不會被記住。重新整理就消失。**
> 刻意不做 localStorage 留存：留存會讓每個人的選單長得不一樣、而且工具內無從清理，
> 「我這台看得到、你那台看不到」是最難查的一種問題。
>
> 這不影響交接——**上傳的圖會內嵌進匯出 zip 裡的 `進度存檔.json`**，
> 同事載入存檔一樣看得到圖，不需要先同步 `img/`。
> 要讓某張圖永久進素材庫，就走上面的正式作法。

### 圖片編輯器

每顆只要選了圖，旁邊就會出現 **「✏ 編輯」**，開啟以 CropperJS 為基礎的編輯視窗。
編輯結果會存成一筆新的自訂素材再套回該顆，**不會改到資料庫原本那筆**（別的欄位可能還在用同一顆圖）。

| 工具 | 用途 |
|------|------|
| 自由比例 / 1:1 / 107:58 | 鎖定裁切框比例 |
| ✂ 套用裁切 | 把目前的裁切框切下來，成為新的一步 |
| 重設視圖 | 圖被拖不見時救回來 |
| ⊕ 加透明邊 | 四周各加 12% 的透明像素 |
| ⊖ 裁到內容 | 自動裁到「所有不透明像素的外接矩形」 |
| 去白底（保留內部白色） | 邊界泛洪去背（見下） |
| 連內部白色一起去 | 全域門檻去背 |
| 容差滑桿 | 多接近白才算白（0–120） |
| ↩ 復原 / ↪ 重做 | 編輯器內的步驟歷史，也吃 Ctrl+Z / Ctrl+Y |

#### 擴大裁切範圍、填透明像素

裁切框用 `viewMode: 0`，**可以拖到圖片外面**，多出來的部分在輸出時是透明像素
（CropperJS 的 `getCroppedCanvas()` 預設 `fillColor: 'transparent'`）。

但拖裁切框仍受**彈窗容器**限制——圖填滿容器高度時上下根本拖不出去。
所以另外做了 **「⊕ 加透明邊」**，直接改工作圖的畫布尺寸，不受容器大小影響，比例也精確可預期。
拖裁切框留給細部微調。

**這有什麼用**：icon 在 107×58 的框裡是 contain 縮放，加一圈透明邊之後圖會變小、留白變多——
這是唯一能讓某一顆看起來比別顆小、或往某個方向偏移的方法。

#### 去白底

兩種模式，差別是**內部的白色會不會被打穿**：

- **去白底（保留內部白色）** ← 預設，多數廠商 LOGO 要的是這個
  從四邊往內泛洪，只移除「跟外框連通」的白色。LOGO 內部被顏色包圍的白字、白色圖標、
  白色高光因為連不到邊界，會**完整保留**。
- **連內部白色一起去**
  不管連不連通，所有夠白的像素一律打掉。用在白底黑線稿、或鏤空處本來就該透明的圖。

實測（100×100 測試圖：白底 + 藍方塊 + 藍塊正中央的白十字）：

| 取樣點 | 保留內部白色 | 連內部一起去 |
|--------|-------------|-------------|
| 外圍白底 | alpha `0` ✅ | alpha `0` |
| 藍色本體 | `[26,85,204,255]` 完整 | `[26,85,204,255]` 完整 |
| **內部白十字** | **alpha `255` 保留** | alpha `0` 打穿 |

**抗鋸齒邊緣**：LOGO 外緣是「白 → LOGO 色」的漸變，硬砍會留一圈白毛邊。
所以判定不是非 0 即 255，而是留一條 `FEATHER`（32）寬的漸進帶，帶內依離純白的距離給比例 alpha。
實測抗鋸齒紅圓去背後，**貼著透明區的殘留白邊像素 = 0**。

**容差**（`src/render/bgRemove.js`）用 `255 - min(r,g,b)` 當「離純白多遠」，不用亮度——
只要任一通道明顯低於 255 就不算白，淺粉淺藍那種 JPG 壓縮雜訊才吃得掉。實測：

| 底色 | 容差 0 | 容差 24 | 容差 48 |
|------|--------|---------|---------|
| `#ffffff` | 全去 | 全去 | 全去 |
| `#f2f2f2` | alpha 104（部分） | 全去 | 全去 |
| `#e0e0e0` | — | alpha 56（部分） | 全去 |
| `#c8c8c8` | — | alpha 247（幾乎不動） | — |

滑桿不會即時預覽——調好容差後按去背按鈕才會套用。不滿意就 Ctrl+Z 再調，成本很低。

#### 光柵化

**編輯器會把向量 SVG 轉成點陣圖**。為避免糊掉，送進編輯器前會先把圖放大到至少 428px
（icon 框寬的 4 倍）再光柵化，向量放大不失真，所以編輯結果仍然銳利。

## 復原 / 重做

`Ctrl+Z` 復原、`Ctrl+Y`（或 `Ctrl+Shift+Z`）重做，面板最上方也有按鈕。共 **50 步**。

歷史直接存舊的 state 參考、不做深拷貝，因為所有 reducer 都是純函式、不可變更新，
舊物件永遠不會被後續操作污染，存參考就等於存快照。上傳的 base64 圖因為結構共享只有一份。

三個刻意的行為：

1. **連續打字合併成一步**。同一欄 700ms 內的連續輸入算同一步，不會一個字一個字倒退。
   停頓超過 700ms 之後再打就算新的一步。
2. **載入進度存檔算一步**。那個動作會連發十幾個 action，用 `store.beginBatch()` /
   `endBatch()` 包成單一步歷史（同理，圖片編輯完的「加素材＋套用」也是一步）。
3. **游標在文字框裡時也走我們的 undo**（攔截並 `preventDefault`）。
   輸入框的原生 undo 只會還原 `input.value`、state 不會跟著回去，兩邊就對不上了。
   例外：注音/倉頡**組字中**不攔（Ctrl 組合鍵是輸入法的），圖片編輯器開著時也不攔
   （交給編輯器自己的 undo，兩層歷史不能打架）。

> 已知取捨：undo 到「上傳某張圖之前」，那張圖會從素材庫消失。
> 因為上傳本來就不做留存，這裡沒有「畫面上沒了、硬碟上還在」的不一致。

## 素材檔案本身的要求

`tools/build-icon-manifest.js` 產出的每一筆長這樣（**這個檔案是產生的，不要手改**）：

```js
{
  id: "主會場",               // 由檔名決定，改檔名 = 換一顆新素材
  displayName: "主會場",      // 選單顯示名稱，就是檔名
  type: "icon",              // 一律 icon；LOGO 請走每一格的「⬆ 上傳」
  src: "data:image/png;base64,...",  // 點陣圖
  // svg: "<svg ...>...</svg>",       // 向量圖改用 svg 欄位（字串）
}
```

> **SVG 一定要有 `xmlns="http://www.w3.org/2000/svg"`**。少了它瀏覽器會直接拒絕載入這張圖，
> 畫面上該格會退回虛線框，而**匯出會被擋下並明確報錯**（不會交出缺圖的成品）。

**PNG 素材要用真正的透明像素做鏤空。** 目前 `img/` 裡那 20 張都是「單色橘 + 透明鏤空」，
形狀完全存在 alpha 通道——這正是單色覆蓋濾鏡最理想的輸入。若把鏤空處畫成不透明的白色，
換色時那塊白會一起被染成橘/灰，鏤空效果就沒了。

**`type` 全部是 `"icon"`**（反白套橘/紅、未選轉灰）。廠商 LOGO 需要保持原色，
但改 manifest 會被重跑蓋掉，所以 LOGO 走每一格的「⬆ 上傳 → 加為廠商 LOGO」。

**製作 icon 的建議**：單色線稿請把要被換色的地方寫成 `fill="currentColor"`，
系統就能用最高品質的方式換色。若沒寫 currentColor（或是點陣圖），系統會退而用
「整片染色」的濾鏡處理，效果通常也可以，但細節較不可控。
廠商 LOGO 則直接寫死正式色票並把 `type` 設成 `"logo"`。

## 模板版位怎麼調

[src/templates/templates.js](src/templates/templates.js) 最上方的 `window.LAYOUT` 就是全部的
版位常數（畫布尺寸、白底高度、icon 框、各段間距、字級字重），`window.TEMPLATES` 則是各顆數
的水平中心點。要改版位直接改這些數字即可，**不需要動任何渲染邏輯**。

## 技術限制與因應（給之後要維護的人看）

- **`file://` 下 `fetch()` 讀本機檔案會被 CORS 擋掉**：所以 `templates.js`、`manifest.js`
  都是用 `<script>` 標籤載入的資料檔，不是 `.json`。
- **`file://` 下把本機圖片畫進 canvas 再匯出會被判定 tainted canvas 而丟 `SecurityError`**：
  實測確認過，只要 icon 是用相對路徑（`<img src="icons/x.svg">`）載入就會中這個雷。
  因應方式是一律轉成 `data:` URI 再餵給 `Konva.Image`——data URI 不會讓 canvas 變 tainted，
  匯出因此在 `file://` 下完全正常。這也是 manifest 把 SVG 內嵌成字串的原因之一。
- **Konva 9 的 Node 沒有 `isDestroyed()`**：`render/canvas.js` 用自己的世代計數器
  （`renderGeneration`）判斷非同步載入完的圖片是否還屬於當次繪製，不要改用 `.isDestroyed()`。
- **只有 viewBox、沒有 width/height 的 SVG**，被當成 `<img>` 載入時拿不到正確原始尺寸，
  等比例縮放會算錯。`colorTheme.js` 的 `ensureSvgSize()` 會依 viewBox 自動補上。
- **中文輸入法（IME）與面板重繪**：`ui/panel.js` 打字時**刻意不重建輸入框 DOM**——
  `SET_SLOT_TEXT` 只會就地更新字數計數器（`syncTextRow`），不走整個面板重繪。
  同時用 `compositionstart` / `compositionend` 判斷組字狀態，組字期間完全不 dispatch。
  這兩件事缺一不可：先前每按一個注音鍵就 dispatch → 面板重繪 → 輸入框被換成新節點 →
  IME 組字被打斷，注音符號卡在欄位裡選不了字。**之後若要改動面板渲染邏輯，請務必保留
  這個特性，並實際用注音/倉頡測過再合併。**
- 沒有前端框架、沒有建置流程，全部是傳統 `<script>` + `window.XXX` 全域物件，
  **依賴 index.html 裡的載入順序**。這是刻意的取捨，換取「雙擊就能用」。

## 目前已知限制

- 內建 icon 只有 5 筆示意用的幾何圖形，需要換成正式素材。
- 批次匯出是「單選模式」：N 顆固定輸出 N 張、每張各反白一顆，不支援自訂多顆組合。
