# 01｜系統總覽與功能地圖

文件狀態：現行程式已確認；部分外部服務行為需實機驗證

盤點日期：2026-08-26

## 1. 一句話定義

BOD 是一套以瀏覽器為執行環境的靜態前端工作台，將工單資料、版位 schema、商品/品牌圖片、配色與文字內容組合成可預覽、可編輯、可下載的電商素材；同一專案內還整合了吸底圖編輯器、曝光資源 JBP 編輯器，以及 PSD/CSS 版位產製與 QA 工具鏈。

## 2. 產品邊界

### 2.1 包含範圍

- BOD 主工作台：版位選擇、版配、工單匯入、全部版位預覽、PNG/XLSX/JSON 匯出、維護檢視。
- 版位定義引擎：以 `block.json` 的圖層與欄位描述，動態產生版位。
- 吸底圖便捷編輯器：多組 banner、多 slot、icon/文字模式、專案檔、批次 PNG/ZIP 匯出。
- 曝光資源 JBP：多種 HTML/CSS 版型、圖片與文字編輯、配色、批次下載、工單載入、禁用語、回饋管理。
- 生產與品質工具：PSD 匯出 CSS 解析、block 產生、座標校準、參考圖量測、差異與文字驗證。

### 2.2 不包含範圍

- 沒有後端 API 作為 BOD 主流程的必要依賴。
- 沒有 package manager、build pipeline 或正式 CI 設定檔。
- 不應把 `jbp/firestore.rules`、`jbp/storage.rules` 解讀成整套 BOD 已有完整後端服務；它們屬於 JBP 回饋/雲端資產相關設定，實際部署狀態仍需另行確認。

## 3. 使用者與工作成果

| 使用者角色 | 主要操作 | 產出 |
| --- | --- | --- |
| 版位/素材製作者 | 選版位、填文字、上傳圖片、調整配色與排列 | 預覽畫布、PNG、工單 JSON/XLSX |
| 設計/製作人員 | 編輯吸底圖或曝光資源、套用背景、校正文字/圖片 | PNG、ZIP、可續編輯專案檔 |
| 版位工程維護者 | 新增/修補 `block.json`、更新 manifest、檢查參考圖 | 可被主工具載入的版位 schema |
| QA/主管 | 維護頁查看註冊版位、執行差異與文字檢查 | 驗證報告、修正紀錄、風險清單 |

## 4. 功能地圖

### 4.1 BOD 主工作台

入口：[`index.html`](../index.html)

- 首頁：工具入口卡片與目前工作狀態。
- 工單生成器：依版位家族與等級選擇版位、填寫欄位、配置 MSBN、嵌入吸底圖工具。
- 匯入工單：讀取 `.xlsx`/`.json`，將工單轉為可編輯畫布；也可以手動按「載入工單生成器版配」把生成器當下的選擇載入進來。
- 曝光資源：嵌入 [`jbp/jbpbn.html`](../jbp/jbpbn.html)，延遲載入以降低主頁初始負擔。
- 維護：載入 active 版位與候選 schema，檢視註冊狀態與下載全部版位資料。

### 4.2 兩條主要素材流程

```text
版位 schema + 文字/圖片
        │
        ├─ BOD 版位生成器 ──> 版配狀態 ──(手動按鈕)─> 匯入工單畫布 ──> PNG
        │                                      └────> JSON / XLSX
        │
        ├─ 吸底圖編輯器 ──> Konva 畫布 ──> PNG / ZIP / 專案 JSON
        │
        └─ 曝光資源 JBP ──> 多版型 iframe 預覽 ──> PNG / ZIP / 狀態檔
```

### 4.3 三個子系統的責任邊界

| 子系統 | 根目錄 | 主要 renderer/state | 與其他系統的連接 |
| --- | --- | --- | --- |
| 主 BOD | 根目錄、`core/`、`blocks/`、`JS/` | `BNCore`、`BNSchemaRenderer`、根頁面 state | 直接管理工單與 schema；嵌入 bottom/JBP iframe |
| 吸底圖 | `bottom/` | Konva canvas、Redux-like store | 可獨立開啟，也可透過 `parentBridge.js` 被主 BOD 嵌入 |
| 曝光資源 JBP | `jbp/` | HTML/CSS iframe runtime、外掛 state | 由主 BOD iframe 嵌入；各版型透過 `postMessage` 接收共用內容 |

## 5. 目前規模摘要

以下為 2026-08-26 從現行檔案統計出的基線：

- `blocks/` 有 129 份實體 `block.json`。
- `blocks/index.js` active registry 有 107 個 ID：72 個 subarea 欄位版位、35 個 MSBN 欄位版位。
- active 與實體 schema 不完全相同；另有維護頁候選版位與未列入 active registry 的舊命名。
- 主 BOD 的畫布寬度為 1200；一般 subarea/MSBN row 高度為 350，MSBN 大版位另有 1200×400/430，吸底圖為 1200×150。
- JBP 目前由 `BN_LAYOUTS` 宣告 17 種 HTML 版型。

完整數量、尺寸與 active/legacy 邊界見 [10｜版位資產與目錄清冊](./10-版位資產與目錄清冊.md)。

## 6. 重要設計決策

### 6.1 Schema 驅動，而非每個版位各寫一套 renderer

版位以圖層陣列描述，欄位從 layer metadata 推導；共用 renderer 依 `image`、`rect`、`circle`、`text` 等 layer type 產生畫面。這讓新增版位主要集中在資料檔與產製工具，但也表示 schema 欄位名稱、z-order、座標與 theme role 都是契約。

### 6.2 生成器與匯入畫布刻意分成兩個狀態邊界

目前「工單生成器」編輯期間不會自動把每次變更推進匯入工單畫布；使用者必須明確按下「載入工單生成器版配」。這避免匯入畫布在編輯期間持續被重建，並保留匯入畫布自己的圖片與文字操作。

### 6.3 JBP 與吸底圖採 iframe/bridge 隔離

兩個子工具都有自己的 CSS、狀態與匯出流程，主頁只負責載入、顯示與必要的資料橋接。修改其中一個子系統時，不應假設可以直接讀取主頁 DOM；應透過既有 `postMessage` 或明確 API。

## 7. 目前已知的工程特性

- 主要程式以 classic script、全域 namespace、inline script 為主。
- 沒有正式 build step；檔案載入順序本身就是依賴管理的一部分。
- 部分依賴由 CDN 動態載入，網路、快取、CORS、`file://` 權限都會影響使用體驗。
- 根 `index.html` 是大型 monolith，修改前必須先找出功能區塊與既有 state/storage key，避免重複宣告或破壞事件綁定。
