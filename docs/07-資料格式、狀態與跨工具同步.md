# 07｜資料格式、狀態與跨工具同步

文件狀態：現行程式字串、資料結構與主要流程已確認

盤點日期：2026-08-26

## 1. 資料流總覽

```text
XLSX / JSON / 圖片
       │
       ├─ 主 BOD parser ──> generator/import state ──> schema renderer ──> PNG/XLSX/JSON
       │
       ├─ bottom importer ──> bottom store ──> Konva ──> PNG/ZIP/project JSON
       │
       └─ JBP importer ──> shared editor state ──> layout iframes ──> PNG/ZIP/state JSON
```

三個子系統的資料模型不相同，只有在明確 bridge（按鈕、工單 parser、postMessage、共用 storage key）處才互通。

## 2. 主 BOD 工單與快照格式

### 2.1 生成器 state

主生成器的核心 state 以以下概念保存：

```text
GeneratorState {
  group,
  slots,
  msbn
}
```

其中 `slots` 表示版位選擇/順序與欄位資料，`msbn` 表示 MSBN 相關選擇與資料。實際 export 由 `buildWorkOrderGrid`、`exportWorkOrderJSON`、`exportWorkOrderXlsx` 等函式產生，欄位契約受 `wo-fields`、`wo-msbn-fields` 與 active block schema 共同約束。

### 2.2 匯入畫布 state

localStorage key：`wo_import_state_v1`

目前保存的概念格式：

```json
{
  "version": 2,
  "source": "…",
  "generatorSignature": "…",
  "columns": [
    {
      "blockId": "…",
      "data": {},
      "header": "…",
      "band": "…",
      "sourceKey": "…"
    }
  ]
}
```

`source` 用來辨識匯入來源，`generatorSignature` 用來辨識按鈕載入的生成器選擇；它們不應被當成使用者文字資料本身。

### 2.3 匯入快照

`buildImportSnapshot()` 產生：

```json
{
  "type": "wo_import_snapshot",
  "version": 2,
  "savedAt": "…",
  "source": "…",
  "generatorSignature": "…",
  "columns": [
    {
      "blockId": "…",
      "header": "…",
      "band": "…",
      "sourceKey": "…",
      "data": {}
    }
  ],
  "uploadedImages": [
    {"name": "…", "url": "…", "baseUrl": "…"}
  ],
  "theme": {},
  "imageZoomWeights": {},
  "imageOffsets": {}
}
```

快照會把可用的 blob URL 轉成 data URL，目的是讓下載或再次載入不依賴短命的 `blob:` URL。

## 3. 主 BOD localStorage keys

目前程式可見的主要 key：

| key | 用途 |
| --- | --- |
| `wo_canvas_state_v1` | 生成器畫布狀態 |
| `wo_family_names_v1` | family 名稱/顯示設定 |
| `wo_unlocked_v1` | 維護/鎖定狀態 |
| `wo_import_state_v1` | 匯入工單 state |
| `wo_import_zoom_v1` | 匯入畫布縮放 |
| `wo_import_theme_v1` | 匯入畫布主題 |
| `wo_shared_canvas_bg_v1` | 主頁與子工具共享背景 |
| `wo_shared_exposure_text_v1` | 共享曝光資源文字 |
| `wo_level_v1` | 目前選擇的等級 |
| `wo_canvas_zoom` | 生成器畫布 zoom |
| `wo_last_view` | 上次 view |

根頁面另有 `WO_CACHE_KEYS` 集中列出一批需要清除或管理的快取 key。新增持久化資料時，應把 key 加入集中管理，並在文件中補登。

## 4. 主 BOD 的同步邊界

### 4.1 生成器 → 匯入工單

現在是「明確按鈕觸發」而不是即時同步：

```text
Generator state ──(按載入工單生成器版配)──> Import columns/state
```

這個 bridge 會更新匯入畫布的版位與資料，但匯入畫布接手後可以獨立修改。不要在 generator render、view switch 或 input listener 中偷偷呼叫相同載入函式。

### 4.2 匯入畫布 ↔ JBP

主頁使用 `wo_shared_canvas_bg_v1`、`wo_shared_exposure_text_v1` 等 key 搭配 `pushExposureOverviewText`、`syncImportedExposureOverviewText`、`pushImportBgToExposure`、`syncImportBgFromExposure` 做有限度同步。這不是完整雙向資料庫；應明確區分「共享摘要/背景」與「完整版位內容」。

### 4.3 主頁 ↔ iframe

iframe bridge 應遵守：

- parent 等 child ready 後再送需初始化的資料，或允許 child 重播 ready 後補送。
- payload 需要版本或 type，避免把一般 window message 誤判為工具事件。
- child 的完整內部 state 不應被 parent 直接改寫。
- download/snapshot 應由實際擁有 DOM/canvas 的子系統完成。

## 5. 吸底圖 project JSON

格式定義：[`bottom/src/state/projectFile.js`](../bottom/src/state/projectFile.js)

| 欄位 | 說明 |
| --- | --- |
| `format` | `sticky-banner-project` |
| `version` | 目前為 2 |
| `savedAt` | 存檔時間 |
| `activeBannerIndex` | 目前 banner |
| `sharpen` | 匯出銳化設定 |
| `banners` | banner/slot/顏色/圖示/文字資料 |
| `customIcons` | data URI 圖示 |

v1 的單 slot 格式會被包裝成 v2，這是現行相容策略。任何 schema 變更都要加入 migration 與壞檔錯誤訊息。

## 6. JBP persistence

JBP 使用雙層保存：

- IndexedDB：`bn_editor_state_db` / `states` / `current`，保存完整 state 與大型圖片。
- localStorage：`bn_editor_state_v1` 與 full/light fallback，保存可快速啟動或無 IndexedDB 時的退路。

除錯順序建議：先記錄資料來源與 version，再分別檢查 IndexedDB、localStorage、iframe 的 runtime state；不要在未備份的情況下直接清除全部。

## 7. XLSX 邊界

目前至少有三種 XLSX 消費者：

| 消費者 | 解析器 | 目的 |
| --- | --- | --- |
| 主 BOD | ExcelJS 4.4.0 | 生成/匯出工單、解析自有工單 |
| bottom | SheetJS 動態 CDN | 吸底圖工單匯入 |
| JBP | SheetJS 動態 CDN | 工單、版位詳情表、banwords |

同一個 `.xlsx` 不代表三個 parser 的欄位語意相同；修改工單欄位時要分別跑三個入口的解析測試。
