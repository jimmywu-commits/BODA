# 03｜主應用與工具

文件狀態：現行程式已確認

盤點日期：2026-08-26

主入口：[`index.html`](../index.html)

## 1. View 結構

主頁的 view：

| View | 主要用途 | 內容來源 |
| --- | --- | --- |
| `home` | 舊工具入口（左側已無按鈕，只剩網址 `#home` 進得去） | 根頁面 HTML/inline JS |
| `generator` | 版位生成器（暫時下架，入口隱藏） | 根頁面 + `core/` + `blocks/`；含 bottom iframe |
| `upload` | 匯入工單：STEP 1 工單試算表、STEP 2 圖片、上傳暫存檔 | 根頁面（元件 id 沿用 `import-drop`、`import-img-*`、`btn-upload-snapshot`） |
| `exposure` | 曝光資源 | `shopee/index.html` iframe |
| `import` | 活動頁資源：MSBN／副區畫布的編輯、預覽與下載 | 根頁面 + schema renderer |
| `color` | 取色工具 | `shopee/color/color-tool.html` iframe |
| `bottom` | 吸底工具 | `bottom/index.html` iframe |
| `maint` | 版位維護、候選 schema 與全部資料下載（按鈕隱藏） | 根頁面 + block loader |

切換通常由 `showView` 統一處理；嵌入頁面採 lazy-load 或 iframe ready 流程，避免首頁初始化時立即啟動全部子工具。沒有記錄（網址 hash、`wo_last_view`）時第一次打開到 `upload`。

`upload` 與 `import` 是同一份匯入資料的兩頁：在 `upload` 上傳時 `view-import` 是隱藏的，畫布照常在背景排版；`showView('import')` 會在顯示後重掃圖片框（`BNImageLayout.scanAndProcess`）並重新定位超過字數的紅框（`scheduleImportTextLimitMarks`）。匯入與畫布操作的訊息都寫在 `upload` 頁的 `#import-log`，活動頁資源左欄的 `#import-canvas-log` 用 MutationObserver 照抄一份。

## 2. 首頁與導覽

主選單提供 Home、工單生成器、曝光資源、匯入工單、維護等入口。現行主選單與匯入工具列採線性 SVG icon：

- `fill:none`
- `stroke:currentColor`
- round line cap/join
- 主選單約 1.75～1.8px stroke

新增工具列 icon 時應優先重用既有 `lineIcon(name)` 或相同 SVG 規格，避免再次引入 emoji、填色 icon 或不同視覺語言。

左側欄最下方的支援按鈕依序是：清除重置（`#boda-reset-all`，紅色虛線、order 19）、使用教學（互動導覽）、使用手冊（另開 `manual/index.html`）、教學影片、使用反饋表（`boda-help-script`，靠 CSS `order` 19～23 排序）。清除重置會停掉各頁自動存檔，刪掉 `wo_`／`bn`／`boda`／`hbn-` 開頭的 localStorage／sessionStorage 與 IndexedDB `boda-import-persist`、`boda-bottom-persist`、`bn_editor_state_db`、`hbn-color-tool`，保留 `bn-layouts`（只清勾選）、反饋表草稿與「新功能」已讀記號，再重新整理到匯入工單。

曝光資源的版位 iframe 是延遲載入（`shopee/index.html` 的 `bnLazyStart`）：畫面上下 800px 內的先載入，其餘捲到附近才設定 `src`；下載全部（`downloadAll`）前會呼叫 `_bnLoadAllPreviews()` 把剩下的載完。教學影片網址填在 `videoUrl`，留空時按下只顯示「準備中」提示。

左側製作流程（2026-11-10 起，`WORKFLOW_STEPS`＋CSS `order`）：匯入工單（`upload`）→ 曝光資源（BN 先做）→ 活動頁資源（`import`，MS）→ 取色工具 → 吸底工具 → 整包下載。目前步驟下方有「完成 ›／略過 ›」（`#step-actions`），狀態存在 `boda_workflow_step_status_v1`，上傳新工單時重設；暫存檔帶著狀態還原，舊暫存檔沒有 `upload` 時視為已完成。螢幕高度不到 820px 時縮小步驟間距，仍放不下時左側欄可以捲動。

## 3. 工單生成器

### 3.1 三個子分頁

| 分頁 | 負責內容 |
| --- | --- |
| `subarea` | A～F 家族的版位選擇與版配 |

| `sticky` | 將 [`bottom/index.html`](../bottom/index.html) 嵌入為吸底圖工具 |

### 3.2 家族與混搭規則

目前家族摘要：

| Group | Family | 規則 |
| --- | --- | --- |
| `AB` | A、B | 可混搭 |
| `CDE` | C、D、E | 可混搭 |

基礎畫布設定：寬 1200、一般列高 350。家族資料中的尺寸與每列上限：

| Family | 單位寬×高 | 每列上限 | active item 數 |
| --- | ---: | ---: | ---: |
| A | 400×350 | 3 | 19 |
| B | 400×350 | 3 | 20 |
| C | 600×350 | 2 | 13 |
| D | 600×350 | 2 | 13 |
| E | 600×350 | 2 | 6 |
| F | 300×350 | 4 | 1 |

### 3.3 等級設定

主頁目前的 `LEVELS`（2026-11-10 更新，顯示名稱＝工單總覽的包套名稱；「-」寫成 0）：

| key | 顯示 | 三大保障 | 副區 | 基本 MSBN | 額外廠商自製 MSBN | 吸底 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| `brand_star_mega` | 大促 Brand star | 1 | 1 | 8 | 8 | 1 |
| `brand_star_mega_zj` | 大促 Brand star 資交 | 1 | 1 | 4 | 8 | 1 |
| `ad_multi` | AD單買(多店活動) | 1 | 1 | 8 | 0 | 1 |
| `ad_bn_only` | AD單買(BN Only) | 0 | 0 | 0 | 0 | 0 |
| `bod_a_plus` | A BOD+ | 1 | 1 | 8 | 8 | 1 |
| `bod_a` | A BOD | 1 | 1 | 8 | 8 | 1 |
| `bod_a_plus_zj` | A BOD+(資交) | 0 | 0 | 0 | 8 | 1 |
| `bod_a_zj` | A BOD(資交) | 0 | 0 | 0 | 8 | 1 |
| `jbp_multi` | B級 JBP(多店活動) | 1 | 1 | 3 | 0 | 1 |

- 預設 level 是 `brand_star_mega`，持久化 key 是 `wo_level_v1`。舊 id 的對應：`mdd`→`bod_a`、`mdd_zj`→`bod_a_zj`，其餘退回預設；`jbp_multi` 現在是獨立等級。
- 等級下拉有五處，彼此同步：工單生成器（`#level-select`）、匯入工單（`#upload-level-select`）、活動頁資源（`#import-level-select`）、吸底（`#bottom-level-select`）、曝光資源 iframe（`boda-level-plugin.js` 的 `#lv-select`，以 `wo-level` postMessage 互通）。
- 活動頁資源依等級呈現（`importLevelHiddenIndexes()`）：最上面一排副區看 `subarea`，工單標成「三大保障_」的段看 `guarantee`，其餘每一段算一張 MSBN、只呈現前 `msbnMax` 張，吸底看 `bottom`。工單資料全部保留，只是不畫、不下載，切換等級會再出現。
- 曝光資源讀 BODA 根目錄的 `MS與BN曝光版位.xlsx`：D 欄是等級名稱，L:X 是 13 個曝光資源版位，只有值為 `v`（或相容勾選值）的欄位會顯示。`MALL HBN` 對應 `HBN` 版型，`Campaign Card` 對應 `SCBN_APP`／工單 key `SCPN`；沒有選配分類，也不會無條件補 LPBN。
- 曝光資源商品區由 `boda-level-plugin.js` 插入「全體商品影子顏色」。固定 HEX 存在 `bn_global_product_shadow_color_v1`，由父頁 `_bodaApplyExposureShadowColorSetting()` 使用既有序列重製管線一次更新全部商品；沒有固定值時才沿用背景 HSL 建議色。更新一律送 `bn-product-update-image`（`keepScale: true`），不 remove/add 商品，所以位置、大小、裁切、旋轉、圖層與各版位 layout 不變。單品影子視窗隱藏顏色欄，只保留開關與幾何設定。

## 4. 生成器到匯入工單

這是目前最容易被誤解的流程：

1. 使用者在生成器選版位、排順序、填資料。
2. 生成器 state 以 `group`、`slots`、`msbn` 等結構保存。
3. 生成器編輯中不會自動改寫匯入工單畫布。
4. 使用者按下匯入工單上方的「載入工單生成器版配」按鈕。
5. `loadGeneratorSelectionIntoImport` 將目前生成器選擇轉成匯入欄位。
6. 匯入畫布接手後，使用者可繼續獨立編輯文字、圖片、配色與順序。

這個手動邊界是刻意設計，不能在 `showView` 或 generator 每次 render 時恢復自動同步，否則會覆蓋匯入畫布上的後續編輯。

## 5. 匯入工單

### 5.1 輸入

- 自有 JSON / JSON 快照。
- 自有 XLSX。
- MSBN 工單欄位。
- Subarea 工單欄位。
- 生成器目前選擇（透過明確按鈕載入）。
- 圖片檔與匯入畫布快照。

### 5.2 主要區塊

| 區域 | 能力 |
| --- | --- |
| 匯入工單頁（`view-upload`） | 等級、STEP 1 工單（`#import-drop`、`#import-log`、工單總覽的曝光資源版位 `#upload-exposure-status`）、STEP 2 圖片（`#import-img-drop`、選擇圖片資料夾、已上傳張數 `#upload-img-status`）、上傳暫存檔 |
| 活動頁資源左欄 | 等級、狀態列、商品影子、統一顏色（不含背景色）、全部版位預覽、清除畫面、下載 |
| 中央畫布 | 版位欄位預覽、文字/圖片編輯、依欄位串接多欄版配 |
| 右側工具列 | 文字欄位操作、圖片替換/編輯/刪除/重設、下載 PNG、編輯快照 |

活動頁資源的統一顏色不提供背景色（`renderImportColorPanel` 濾掉 `bg`；「全部還原」也不動背景色），背景色在曝光資源或取色工具調整後經 `wo_shared_canvas_bg_v1` 帶過來。

CTA 底色跟曝光資源連動，但 MS 版位不用白色（`importCanvasCtaColors`）：連動來的 CTA 對白色 CR < 1.3 時，從主標色、副標色、品牌橘 `#ee4d2d`、背景色的深色（同色相壓暗到亮度 0.03）裡挑「對白色、對背景色兩者較小的對比」最大的，排除黑／灰；字色沒有手動指定就依新底色重算。只影響 MS 畫布（匯入／預覽／維修），曝光資源與取色工具的 CTA 不變；統一顏色的 CTA 色票顯示畫布實際用的顏色並註明原因。

活動頁的圓標底色與 CTA 底色禁止相同。CTA 是曝光資源、取色工具與活動頁共用值，因此衝突時保留 CTA，由 `importCanvasBadgeBg()` 改選圓標色；圓標自動來源先用副標／促標角色，再依品牌橘、金色、藍綠等候選選出與 CTA 有明顯色差且不融入畫布背景的顏色。此規則套用於手動色票、背景同步、工單匯入、暫存還原、維修與下載渲染。

### 5.3 解析與渲染

主要流程函式包括：

- `handleImportFile`
- `parseImportOwnJSON`
- `parseImportOwnJSONMsbn`
- `parseImportXlsxV2Workbook`
- `parseImportXlsx`
- `afterImportParsed`
- `renderImportColumns`

匯入後每個欄位會保留 `blockId`、`data`、`header`、`band`、`sourceKey` 等資訊，以便重新渲染與再次匯出。

### 5.4 畫布操作與同步

- `IMPORT_SYNC` 以 `lockUntil`、`canvasTimer`、`toolTimer` 避免畫布和右側工具列互相觸發無限 scroll feedback。
- 畫布與工具列會 snap 到同一個 current column。
- 匯入背景與 JBP 曝光資源文字可透過 shared localStorage key 做有限度同步。
- 匯入 state 會保存到 localStorage；維護頁的候選版位則以 memory context 為主，不應假設兩者會互相污染。

## 6. 匯出

| 匯出 | 主要函式 | 說明 |
| --- | --- | --- |
| 單一工單 JSON | `exportWorkOrderJSON` | 供自有格式重載與交換 |
| 單一工單 XLSX | `exportWorkOrderXlsx` | 使用 ExcelJS |
| 全部版位 XLSX | `exportAllPlacementsXlsx` | 維護/批次用途 |
| 匯入畫布 PNG | `downloadImportImage` | 使用 html-to-image；匯出前暫時將 strip scale 設為 1 |
| 編輯快照 | `buildImportSnapshot` | 包含欄位、圖片、主題、縮放與偏移 |

PNG 匯出會使用 `resolvedImportBg()` 作為背景，並在可用時注入 `BN_FONTS_EMBED_CSS`，以降低預覽與下載結果的字型差異。

## 7. 維護工具

維護頁會：

- 載入 active registry 的全部 blocks。
- 根據註冊 ID 去除最後一段，推導候選 schema 名稱。
- 載入未註冊但存在的候選 block。
- 以 `refImage` 與尺寸辨識重複或相近版位。
- 提供全部版位資料下載。

因此維護頁看到的數量可能大於主生成器的 active 數量；這是設計上的診斷能力，不代表所有實體 schema 都已正式上線。

## 8. 變更落點速查

| 需求 | 優先修改 |
| --- | --- |
| 新增/修正版位 | `blocks/{id}/block.json`、`blocks/index.js`，必要時同步 `manifest.json` |
| 改 renderer 通用行為 | `core/schema-renderer.js` |
| 改 block 載入/registry | `core/core-engine.js` |
| 改工單解析/匯出/匯入 UI | `index.html` 對應 inline 區塊 |
| 改共用圖片編輯行為 | `JS/image-layout.js`、`JS/editor-plugin.js` |
| 改吸底圖 | `bottom/src/`；不要直接改產生的 icon manifest |
| 改 JBP 共用功能 | `jbp/js/` 或 `jbp/jbpbn.html` |
| 改 JBP 單一版型 | `jbp/html/{layout}.html/.css/.config.css` |
| 改 PSD/CSS 生產規則 | `export/psd-css-toolkit/psdcss/` |
| 改 QA/量測 | `tools/` |
