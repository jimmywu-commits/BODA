# 12｜測試驗證、風險與待改善

文件狀態：現況盤點與工程建議

盤點日期：2026-08-26

## 1. 驗證分層

目前沒有正式的 package script、CI 或完整自動化瀏覽器回歸測試，因此建議採四層驗證：

| 層級 | 目的 | 現有手段 |
| --- | --- | --- |
| L0 靜態 | 檔案、JSON、語法與 diff | `git diff --check`、JSON parse、Node `new Function` |
| L1 結構 | registry、欄位、尺寸與 layer 契約 | `check_workorder_fields.js`、`dump_layout.js`、`diff_css_vs_blocks.py` |
| L2 視覺 | ink、中心、line-height、reference 差異 | `measure_ref_*`、`verify_ink_accuracy.py`、`overlay_check.py`、raster preview |
| L3 實機 | 瀏覽器輸入、iframe、CDN、下載、保存 | HTTP server + Chrome/Edge 手動驗收 |

## 2. 建議的最小驗收矩陣

### 主 BOD

- 首頁切換五個 view。
- 生成器選 A/B、C/D/E、F 家族並確認混搭規則。
- 選一個 MSBN 版位，輸入圖片/文字並下載 JSON/XLSX。
- 編輯生成器後確認匯入畫布不會自動改變。
- 按「載入工單生成器版配」後確認版位與順序正確轉移。
- 上傳 `.xlsx` 與 `.json`，確認 parser、圖片 gallery、欄位資料。
- 匯入畫布編輯文字/圖片/背景，再下載 PNG。
- 匯出/匯入 `wo_import_snapshot`，確認圖片、theme、zoom、offset 保留。
- 維護頁確認 active 與候選版位的差異可辨識。

### 吸底圖

- 2～5 slots 的切換。
- icon 模式與文字替代模式互換。
- banner 新增/刪除、active banner、undo/redo。
- accent color、sharpen、custom icon。
- 工單匯入、專案 JSON save/load、v1 migration。
- PNG/ZIP 匯出與字型失敗訊息。
- 獨立頁和主 BOD sticky iframe 都測一次。

### JBP

- 17 種 layout 是否都能建立 iframe 並回報 ready。
- logo、商品、人物圖、背景與文字廣播。
- 深/淺背景下主標、副標、CTA 底、CTA 字、三角標對比。
- contenteditable、文字上限、banwords 與手動 Excel fallback。
- 單張/批次 PNG/ZIP，檢查 object-fit、偽元素、外部圖片與字型。
- IndexedDB auto-save/load、localStorage fallback、JSON export/import。
- feedback/Firebase 失效時編輯與下載是否仍可用。

## 4. 風險清單

| 優先級 | 風險 | 影響 | 建議 |
| --- | --- | --- | --- |
| P0 | 主頁與 JBP 為大型 monolith/全域 script | 修改容易造成隱性耦合、重複宣告、事件互相影響 | 逐步拆模組；先建立 smoke/regression test |
| P0 | CDN、字型、外部圖片/CORS | parser、渲染、下載可能失敗或輸出空白 | 固定版本、提供 fallback/錯誤、評估 vendor/快取 |
| P0 | active registry 與實體 schema 不一致 | 使用者看不到新/舊版位，維護頁數量誤判 | 建立 registry/schema consistency check |
| P1 | `file://` 與 HTTP 行為不同 | fetch、banwords、字型、iframe 載入失敗 | 提供標準 HTTP server 啟動方式 |
| P1 | html2canvas 與瀏覽器排版差異 | PNG 與即時預覽不一致 | 固定 capture clone、字型 ready、保留後製流程 |
| P1 | localStorage/IndexedDB 舊資料 | 重整後看似沒有採用新預設，或 migration 失敗 | 所有格式加 version，提供可見 reset/backup |
| P1 | 缺少自動化瀏覽器測試 | 回歸問題晚期才發現 | 加入 Playwright smoke tests 與 golden image 檢查 |
| P2 | 根目錄歷史/備份/產物混在一起 | 誤載入、誤修改、部署包過大 | 標記 generated/legacy，建立 artifact policy |
| P2 | JBP Firebase 設定與規則檔 | feedback/管理功能可能因環境不一致失效 | 將部署設定與前端設定分離，定期驗證 rules |
| P2 | 主工具的 PIN/解鎖狀態偏前端 | 只能當 UX gate，不能當安全邊界 | 敏感權限改由後端授權 |

## 5. 待改善路線圖

### 短期

- 建立一個標準本機 HTTP server 與 smoke test 說明。
- 建立 `blocks/index.js` 對所有 `block.json` 的一致性檢查。
- 將 storage key、project version、snapshot version 集中成可查表設定。
- 為主 BOD、bottom、JBP 各保留一份最小可重現測試工單/素材。
- 將本文件集加入每次功能變更的交付 checklist。

### 中期

- 將根 `index.html` 的 inline script 拆成可測試模組。
- 將 JBP layout metadata 與 message contract 結構化。
- 導入 Playwright/類似瀏覽器測試，至少覆蓋載入、匯入、下載、state restore。
- 建立 reference image golden test，設定允許的像素偏差。
- 評估將關鍵 CDN 依賴固定或內包。

### 長期

- 明確分離 source、generated、legacy、runtime asset 目錄。
- 將 schema、工單欄位、配色 role、下載格式建立版本化契約。
- 評估 TypeScript/module 化與 build pipeline，但須先保留既有無 build 部署能力的替代路徑。
- 將 Firebase feedback 與素材編輯主流程解耦成可選 adapter。

## 6. 交付判定

一項變更只有在下列條件都滿足時，才可標記完成：

- 影響範圍內的靜態檢查通過。
- schema/欄位/registry 的結構契約通過。
- 預覽與輸出圖在目標瀏覽器一致。
- 保存、重整、重新匯入仍可恢復。
- CDN/圖片/字型失效時有合理錯誤行為。
- 既有生成器→匯入工單的手動同步邊界未被破壞。
- 相關文件、數量與變更紀錄已更新。
