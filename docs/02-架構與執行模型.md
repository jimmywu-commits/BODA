# 02｜架構與執行模型

文件狀態：現行程式已確認

盤點日期：2026-08-26

## 1. 架構類型

BOD 目前是「無 build 的多入口靜態前端」：HTML、JavaScript、CSS、JSON、圖片與字型直接放在專案目錄，瀏覽器載入後組成工具。沒有 `package.json`、TypeScript 編譯、bundler 或可辨識的正式 CI pipeline。

這個選擇讓檔案容易交接與部署，但也使以下事項成為架構的一部分：

- `<script>` 的順序不能任意調換。
- 相對路徑、目前頁面的 base URL、HTTP server 與 `file://` 行為會直接影響功能。
- 全域函式、全域變數、DOM ID 與 localStorage key 是隱性的 API。
- CDN 版本與動態載入 fallback 必須被當成 runtime dependency 管理。

## 2. 入口與載入拓撲

```text
index.html
 ├─ ExcelJS 4.4.0 (CDN)
 ├─ html-to-image 1.11.13 (CDN)
 ├─ JS/fonts-embed.js
 ├─ JS/render-config.js
 ├─ core/core-engine.js       → BNCore registry + block loader
 ├─ core/schema-renderer.js    → BNSchemaRenderer
 ├─ JS/image-layout.js
 ├─ JS/editor-plugin.js
 ├─ inline application script  → views / state / import / export
 ├─ bottom/index.html iframe    → 吸底圖（生成器 sticky 分頁）
 └─ jbp/jbpbn.html iframe       → 曝光資源（延遲載入）

bottom/index.html
 ├─ Konva 9 (CDN)
 ├─ JSZip 3 (CDN)
 └─ bottom/src/*.js             → store / render / UI / bridge / export

jbp/jbpbn.html
 ├─ jbp/js/index.js             → 17 種 layout registry
 ├─ 4 個核心 plugin 動態載入（加 timestamp 避免快取）
 ├─ feedback config/plugin       → Firebase feedback runtime
 └─ jbp/html/*.html iframe      → 個別版型的 CSS/HTML runtime
```

## 3. 主 BOD 載入順序

`index.html` 的核心外部載入順序是：

1. ExcelJS：產製工單 XLSX。
2. html-to-image：把匯入畫布轉 PNG。
3. `JS/fonts-embed.js`：準備匯出時內嵌字型 CSS。
4. `JS/render-config.js`：共用渲染設定。
5. `core/core-engine.js`：先建立 `BNCore` 與 schema 載入能力。
6. `core/schema-renderer.js`：註冊 `BNSchemaRenderer`，提供 schema → DOM。
7. `JS/image-layout.js`：圖片版面計算與編輯輔助。
8. `JS/editor-plugin.js`：編輯器互動外掛。
9. 根頁面大型 inline script：建立 view、事件、狀態、工單解析與匯出。

若在第 5～8 步前呼叫依賴該 namespace 的程式，通常會得到「函式不存在」或空 registry；這是目前最重要的隱性依賴。

## 4. Core registry 執行模型

檔案：[`core/core-engine.js`](../core/core-engine.js)

核心提供下列全域 API：

| API | 職責 |
| --- | --- |
| `BNCore.registerBlock(def)` | 註冊一個 block definition，驗證 `id/render` 並注入一次 block style |
| `BNCore.getBlocks()` | 取得已註冊 blocks |
| `BNCore.getBlock(id)` | 依 ID 取得 block |
| `BNCore.onRegister(fn)` | 監聽後續註冊事件 |
| `BNCore.renderInstance(blockId, data, opts)` | 以資料渲染 block instance |
| `BNCore.defaultData(blockId)` | 取得欄位預設值 |
| `bnLoadAllBlocks(onDone, basePath, onProgress)` | 讀取 `blocks/index.js` 與各 `block.json` |

`bnLoadAllBlocks` 的正常路徑是：先載入 registry，再平行讀取 active block JSON，最後呼叫 `BNSchemaRenderer.registerFromSchema(schema)`。只有當必要檔案全部成功，才應把全體載入視為完成。

## 5. Schema renderer 執行模型

檔案：[`core/schema-renderer.js`](../core/schema-renderer.js)

renderer 會：

1. 讀取 schema 的尺寸、圖層、可選 repeats 與 layout metadata。
2. 從 image/rect/circle/text layer 建立欄位與 DOM。
3. 將輸入 data 與預設 data 合併。
4. 套用 theme role、圖片吸附、dynamic row、z-order、文字與裁切設定。
5. 依 `opts` 決定是否 editable、是否允許圖片吸附、是否注入 dynamic row 資料。

已知 `opts` 契約包括 `editable`、`theme`、`imageAbsorb`、`forceImageAbsorb`、`dynamicRowRows`。新增 renderer 行為時，優先擴充此契約或 schema metadata，不要在單一版位用不可追蹤的 DOM 特判。

## 6. iframe 隔離模型

### 6.1 主頁 → 吸底圖

主頁在 `generator` 的 sticky 分頁顯示 `bottom/index.html?embed=generator`。吸底圖透過 `parentBridge.js` 判斷 `<html class="embed-generator">`，接收父頁傳來的工單或資料，並把操作結果留在子工具自己的 store。

### 6.2 主頁 → JBP

主頁在曝光資源 view 內 lazy-load `jbp/jbpbn.html`。JBP 本身再建立多個 layout iframe；主 JBP 頁面負責共用文字、顏色、logo、商品、背景與下載，而 `layout-runtime.js` 負責每個版型內部的實際排版。

### 6.3 iframe 通訊原則

- 只用既有 `postMessage` 事件與 payload；不要跨 iframe 直接操作對方 DOM。
- 新增 message type 時，應同時在 sender、receiver 與本文件的資料流表中註冊。
- message handler 必須容忍 iframe 尚未 ready；JBP 目前有 ready/snapshot 類型的流程，應沿用而非以固定 timeout 取代。
- 跨來源情境下應檢查 `event.origin`；目前部分 legacy bridge 仍偏向以 message type/來源判斷，屬於應改善區域。

## 7. 瀏覽器 API 與平台依賴

| API/能力 | 使用處 |
| --- | --- |
| `FileReader`、`Blob`、`URL.createObjectURL` | 上傳工單、圖片、專案檔與快照 |
| `fetch` | 載入 schema、背景清單、字型、banwords、外部資源 |
| `localStorage`、`sessionStorage` | BOD 選擇/畫布/主題、JBP 輕量備份 |
| `indexedDB` | JBP 完整狀態與圖片資料 |
| `postMessage` | 主頁與兩種 iframe bridge |
| `ResizeObserver` | 畫布/viewport responsive sizing |
| `canvas`、`toDataURL` | 圖片編輯、色彩取樣、下載後製 |
| `html-to-image`、`html2canvas` | DOM/iframe 匯出 |
| `Konva` | 吸底圖 scene graph 與畫布互動 |
| `FontFace`、`document.fonts` | 吸底圖與匯出字型準備 |

## 8. 執行環境要求

### 建議

- 以 HTTP server 提供專案根目錄，避免 `file://` 對 fetch、Excel、字型與 iframe 造成限制。
- 確認 CDN 可連線；正式部署應考慮固定版本、鏡像或 vendor 依賴。
- 用瀏覽器 DevTools 檢查 console、Network、iframe ready 與 localStorage/IndexedDB。

### 不建議

- 直接雙擊 HTML 後判斷所有載入失敗都是程式 bug。
- 在未清除或檢查舊狀態的情況下，用 localStorage 結果推論程式目前預設值。
- 任意更換 script 順序、DOM ID、storage key 或 global function 名稱。

## 9. 架構弱點

- 根入口與 JBP 部分檔案偏大型，缺少模組邊界的編譯期保護。
- CDN 失效會影響工單解析、圖片匯出、Konva、JSZip、字型與 Firebase 回饋等能力。
- schema registry、實體 block 與維護候選清單可能不同步。
- 沒有自動化瀏覽器回歸測試，現有驗證主要是 Node/Python 腳本與人工檢視。
