# 11｜開發維護與變更指南

文件狀態：現行架構基線

盤點日期：2026-08-26

## 1. 變更前的基本原則

1. 先判斷變更屬於主 BOD、bottom、JBP、schema 或工具鏈。
2. 找到真正的 source of truth，不要直接修改產物或備份檔。
3. 先記錄現有輸入、輸出、storage key、iframe message 與預覽截圖。
4. 小範圍修改後先跑靜態語法/差異檢查，再做瀏覽器驗收。
5. 同時檢查預覽、下載、重載與錯誤路徑。

## 2. 常見需求的正確落點

| 需求 | 優先落點 | 不建議 |
| --- | --- | --- |
| 新增/修正主 BOD 版位 | `blocks/{id}/block.json`、必要時 `blocks/index.js` | 在 `index.html` 為單一版位寫一套硬編碼 DOM |
| 通用 schema 渲染行為 | `core/schema-renderer.js` | 把特判塞入某個 block 的資料值 |
| 版位載入/註冊 | `core/core-engine.js`、registry | 只在瀏覽器 console 手動 register |
| 工單欄位/匯出 | `index.html` 對應 parser/export 函式與 inline field map | 只改 UI label，不改 parser/export |
| 圖片編輯/吸附 | `JS/image-layout.js`、`JS/editor-plugin.js` 或 renderer | 在單一事件 handler 直接改 inline style |
| 吸底圖功能 | `bottom/src/` | 改 `manifest.js` 產物取代 icon source |
| JBP 共用行為 | `jbp/js/`、必要時 `jbp/jbpbn.html` | 複製一份 runtime 到每個 layout |
| JBP 單版型視覺 | `jbp/html/{layout}.html/.css/.config.css` | 改主頁 CSS 期待 iframe 內同步 |
| PSD 產製規則 | `export/psd-css-toolkit/psdcss/` | 手動大量改 JSON 又不回寫 pipeline |
| QA/量測 | `tools/` | 只看肉眼縮放預覽就結案 |

## 3. 新增主 BOD block

### 步驟

1. 取得 PSD/CSS、reference、字型與欄位規格。
2. 用 toolkit 產生 `block.json`。
3. 執行 calibrate、verify、preview 與 overlay/ink 檢查。
4. 檢查 layer type、field、z-order、clip、radius、theme role、圖片吸附。
5. 把 ID 加到 `blocks/index.js`（僅在確認要 active 時）。
6. 更新需要的 `wo-fields`/`wo-msbn-fields` 或 parser map。
7. 測試生成器、匯入工單、維護頁、JSON/XLSX、PNG。
8. 更新 [10｜版位資產與目錄清冊](./10-版位資產與目錄清冊.md) 的數量。

### 不可漏檢

- active registry 與實體資料夾名稱。
- 參考圖路徑與部署後相對路徑。
- 文字最大長度與字面 ink top。
- CTA/背景/副標的 role 關係。
- 下載時的字型、圖片與背景是否仍存在。

## 4. 新增或修改工單欄位

需要同步檢查：

- inline `wo-fields` 或 `wo-msbn-fields`。
- generator 的輸入 UI 與 state。
- `parseImportXlsx*` 與 own JSON parser。
- `renderImportColumns` 的 data mapping。
- `buildWorkOrderGrid`、JSON/XLSX export。
- block schema 中的 field metadata。
- 圖片 gallery、動態列、文字編輯與 snapshot restore。

若欄位只在一個入口能輸入，卻無法被另一個入口解析，應視為契約未完成，不要以「主畫面看得到」當成完成。

## 5. 修改生成器/匯入同步

目前規則是手動載入：

```text
生成器編輯 ──(不自動同步)──> 匯入畫布
       按「載入工單生成器版配」後才轉移
```

修改相關功能時：

1. 保留 `currentGeneratorSignature`、`currentImportSource` 等識別資訊。
2. 不要在 `showView`、generator input、render callback 中偷偷觸發 load。
3. 測試生成器修改後匯入畫布不變。
4. 按鈕觸發後測試版位/順序/資料正確載入。
5. 載入後測試匯入畫布的圖片/文字修改不會被後續 generator render 覆蓋。

## 6. 修改配色或 CTA

先分清楚：

- 主 BOD schema renderer 的 role 顏色。
- JBP 背景取樣/自動 palette。
- bottom 的 icon accent theme。
- UI icon 的線性 stroke。

CTA 目前契約：底色跟副標；文字與三角標跟 CTA 底色做黑/白最大對比反色。修改後要用淺背景、深背景、飽和背景各驗證一次，並檢查 PNG 匯出。

## 7. 修改 bottom

- state/action 變更：先改 `actions.js`、`reducers.js`、`selectors.js`，再接 UI 與 renderer。
- project JSON 變更：增加 version/migration，保留舊版讀取。
- icon 變更：更新 source/manifest 產製流程，執行 `build-icon-manifest.js`。
- 字型/尺寸變更：同步 canvas、viewport、export、使用說明。
- parent bridge 變更：同時測試獨立頁與 `?embed=generator`。

## 8. 修改 JBP

- 單一版型：確認 `.html`、`.css`、`.config.css` 三者與 runtime selector。
- 全部版型：修改 `layout-runtime.js` 或主 plugin，並測試 17 種 layout。
- state：同時測試 IndexedDB、localStorage fallback、清除、重整與匯入/匯出。
- 工單：確認 SheetJS 動態載入、fallback、欄位 map 與直接雙擊/HTTP server 差異。
- 外部服務：feedback 不可用時，編輯/下載主流程仍應可用。

## 9. 版本與快取

- JBP 會對 `index.js` 與四個核心 plugin 加 timestamp；主 BOD 某些 script 也有 query version。
- 變更部署後若畫面沒變，先檢查 Network response、script query、service/browser cache，再判斷程式邏輯。
- 不要刪除使用者 storage 作為第一個除錯手段；先匯出/備份 state。
- 任何 storage key 或 project/snapshot version 變更都要寫 migration/相容策略。

## 10. 交付前檢查

- `git diff --check`。
- JS/Python 靜態語法或既有 QA script。
- 生成器、匯入、bottom、JBP 至少各操作一條 happy path。
- 下載 PNG/ZIP/XLSX/JSON（適用者）。
- 重整/重新載入保存 state。
- 清空/錯誤/外部依賴失敗路徑。
- 更新本文件集與歷史修正紀錄。
