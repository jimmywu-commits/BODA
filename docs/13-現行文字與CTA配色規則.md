# 曝光資源文字配色與自動切換規則

文件狀態：依目前程式實作整理

更新日期：2026-11-06

適用範圍：曝光資源（`jbp/jbpbn.html`）、背景圖庫（`jbp/js/bn-bg-library-plugin.js`）、背景上傳（`jbp/js/bn-editor-plugin.js`）。

> **2026-11-06 配色分工變更**（目前實作在 `shopee/index.html` 的 `bnAutoCtaBackground()`，下列第 6、7、9 節已依此更新）：
> 副標色 → 匯入工單的促標底色；主標色 → CTA 底色、匯入工單的圓標底色。
> 取色工具 `shopee/color/color-tool.html` 的 `finish()`、BODA `index.html` 的 `getExposureAutoCtaBg()` 是同一套算法，三處要一起改。

> 本文件說明「目前會怎麼自動切換」。使用者在色票手動換色後，該色會立即套用；下一次更換背景圖或背景色時，系統會重新建立一組自動配色。

## 1. 一句話總結

系統先判斷文字區的背景明暗，再從背景右側／視覺主區取得色相；主標、 副標、日期以同色系但不同明度建立層級，最後以 W3C 對比值校正。CTA 底色與匯入工單的圓標底色跟隨主標色，副標色則餵給匯入工單的促標底色；CTA 字與三角形在白／黑之間自動選擇最高可讀性。

```text
背景圖或背景色
   │
   ├─ 文字區／左側底色 ──► 判斷深、亮、中間色調
   ├─ 視覺主區／右側顏色 ─► 決定文字色相
   │
   └─ 產生主標／副標／日期／品牌名
          │
          ├─ W3C 對比保護（至少 4.5:1）
          ├─ CTA 底色＝主標色
          ├─ 促標底色＝副標色、圓標底色＝主標色（匯入工單）
          └─ CTA 字＋三角＝白或黑的最大對比色
```

## 2. 何時會自動重新配色

| 操作 | 是否自動重新配色 | 取樣方式 |
| --- | --- | --- |
| 從背景圖庫選背景圖 | 會 | 64×24 縮圖：左半文字區平均色＋右半視覺區主色 |
| 上傳背景圖 | 會 | 背景圖庫的取樣流程會接手；上傳流程另以左上角 1×1 px 鎖定畫布背景，透明像素不採用 |
| 手動更換「背景顏色」 | 會 | 以選定的純色同時作為文字區色與視覺主色 |
| 匯入工單／其他頁面同步背景色至曝光資源 | 會 | 同手動背景色規則 |
| 手動更換主／副／日期／CTA 色票 | 不會重新推算其他文字 | 只套用使用者指定的欄位；直到下次背景改變才重新產生整組自動配色 |

背景圖已套用後，使用者再手動選背景色時，手動色優先，不會被同一張背景圖的延遲取樣覆蓋；換成另一張背景圖才會重新取樣。

## 3. 背景圖怎麼取色

### 3.1 兩個取樣區

背景圖會先縮成 `64 × 24 px` 進行分析：

| 區域 | 取樣規則 | 用途 |
| --- | --- | --- |
| 左半（0–32 px） | 平均色 | 當作 `canvasBg`，也就是文字實際應避開的底色 |
| 右半（34–64 px） | 主色／最多像素色；找不到時使用平均色 | 當作 `visualBg`，用來決定文字色相，讓左側文字與右側視覺保持平衡 |

這就是深色背景時仍能取右側主視覺色做亮文字、黃色背景時會改用相近的橘色系文字的原因。

### 3.2 背景上傳的左上角保護

背景上傳流程會讀原圖左上角 `1 × 1 px` 作為畫布背景鎖定色。若該點透明，維持舊色，不會把透明 PNG 當成黑色，也不會誤吸到 LOGO 主體。

> 左上角取色的目的，是穩定背景色狀態；文字自動配色仍以背景圖庫的文字區／視覺區分析為主。

## 4. 主標、副標、日期、品牌名的自動邏輯

### 4.1 共同原則

- 色相優先參考右側視覺主色，讓文字與右側商品／人物／裝飾圖有色彩關聯。
- 若視覺主色低飽和（飽和度 `< 15%`），改用安全藍色相 `220°`，避免生成灰字。
- 黃色背景（色相約 `38°–78°`）會讓文字色相往橘移約 `12°`，維持一致但不會與黃底混在一起。
- 品牌名 `brandText` 與主標 `mainText` 同色，維持資訊層級一致。
- 所有主／副／日期／品牌文字最終都會經過可讀性保護，目標至少 `4.5:1` 對比。

### 4.2 深色背景：相對亮度小於 0.22

| 文字 | 視覺策略 |
| --- | --- |
| 主標 | 明亮、高彩度的同色系，保有主視覺力度 |
| 副標 | 更亮、較柔和的同色系，通常是整組最亮文字 |
| 日期 | 比主標稍收斂，但仍保持亮色可讀性 |
| 品牌名 | 跟主標相同 |

結果是「深底不再配更深文字」，而是使用由右側視覺主色延伸出的亮色系。

### 4.3 亮色背景：相對亮度大於 0.55

| 文字 | 視覺策略 |
| --- | --- |
| 主標 | 同色系、較深且較飽和 |
| 副標 | 同色系深色，但比主標略柔和 |
| 日期 | 同色系中深色，資訊層級最低 |
| 品牌名 | 跟主標相同 |

結果是亮底不直接使用純黑，而是在同色相中降低明度；例如黃底傾向使用橘／紅橘字，使畫面一致且仍可讀。

### 4.4 中間色背景：相對亮度介於 0.22–0.55

系統會同時建立「同色系深字」與「同色系亮字」，比較它們和文字區背景的對比值，選擇對比值較高的一側，再建立主／副／日期三層級。

## 5. 文字防吃色機制

### 5.1 同色系修正

如果候選字色不夠清楚，系統會維持原色相，逐步往較深或較亮方向調整明度；飽和度至少保留 `42%`，避免變成灰色。

### 5.2 最終安全色

若同色系已無法達到目標對比，才使用下列其中一色：

- 深藍黑：`#00004f`
- 暖白：`#fffefa`

系統比較兩者和背景的對比值，選較高的一色。這也是純紅、純橘等高彩度純背景不會再產生暗紅／暗橘吃色文字的最後防線。

### 5.3 可讀性檢查面板

工具列「其他顏色」下方會顯示文字可讀性檢查：

- 依品牌名、主標、副標、日期分別顯示對比值。
- 有背景圖時，同時檢查畫布背景色與文字區取樣色。
- 任一項低於 `4.5:1` 會標示「可能吃色」；全部達標顯示通過。

這是提醒與驗收工具，不會阻擋下載。

## 6. CTA 自動配色

### 6.1 連動關係

```text
主標色 mainText
   ├─► CTA 底色 ctaBg
   │      └─► CTA 文字 ctaText + CTA 三角符號
   └─► 圓標底色 badgeBg（匯入工單）

副標色 subText
   └─► 促標底色 promoBg（匯入工單）
```

背景自動配色時：

- `ctaBg`＝自動主標色（舊版是副標色）。
- 保底順序，每一步都要對背景對比 ≥ 3：主標色 → 副標色 → 品牌橘 `#ee4d2d` → 主標色。
- 主標色若是黑／灰（CTA 底禁用）：深底時改用純白；對背景不夠就跳到下一步。
- 深底的自動主標是白色，所以 CTA 底色是白色；淺底的自動主標是同色相的深色，所以 CTA 底色是深色。
- `searchImageCtaBg` 也同步為這個 CTA 底色。
- `ctaText` 與 CTA 三角符號同步使用同一色。
- 匯入工單的圓標字色由 renderer 依圓標底色明暗自動調整可讀性（對比 < 3 時改黑／白）。
- 使用者手動指定的促標底色、圓標底色、CTA 底色優先；手動換背景色時，促標底色、圓標底色、CTA 底色都會回到自動。

### 6.2 CTA 字與三角形

CTA 預設為自動模式：

| CTA 底色相對亮度 | CTA 文字與三角形 |
| --- | --- |
| `≥ 0.72`（非常淺） | 黑色 `#000000` |
| `< 0.72`（一般或深色） | 白色 `#ffffff` |

使用者可以手動設定 CTA 文字為任意有效六碼 HEX；手動選色後，CTA 底色變動不會覆蓋這個文字色。下一次背景自動配色重新生成整組色盤時，CTA 會回到該組自動結果。

### 6.3 CTA 底色防呆

CTA 底色禁止：

- 黑、白、近黑、近白。
- 廣義灰色／低飽和色（通道差 `≤ 72` 或飽和度 `≤ 0.30`）。
- 與畫布背景 RGB 色距小於 `96` 的顏色。

命中限制時，系統會改選安全候選色，優先順序為：目前候選／副標／主標 → `#ee4d2d` → `#ff6b35` → `#d0021b` → `#00a0a0` → 深藍候選。這能避免深藍背景（如 `#2540b5`）上出現融入背景的深藍 CTA。

## 7. 手動選色限制與回退

| 欄位 | 手動設定 | 不合法時的處理 |
| --- | --- | --- |
| 品牌名、主標 | 可用純黑與純白（2026-11-06 起，取色工具深底就是配白主標，兩邊才能同步）；仍受「與底色太接近（CR < 1.3）」的吃色防護 | 吃色時改用依底色算出的自動色 |
| 副標、日期 | 禁純黑與純白 | 回退 `#2540b5` |
| CTA 底色 | 禁黑、白、廣義灰、接近畫布背景色 | 改為安全 CTA 色並顯示提醒 |
| CTA 字色 | 可用任何有效六碼 HEX | 無效值時依 CTA 底色回退白／黑自動對比 |

## 8. 特殊曝光版位

| 版位 | 背景與文字配色行為 |
| --- | --- |
| SearchICON 三版位 | 外底固定白色；圓形內仍連動 `canvasBg`。其中 `SearchICON_TEXT` 的文字色連動副標色。 |
| AR、AR_LOGO | 只連動背景色，不連動背景圖；AR 文案色跟副標色。 |
| 首頁 LOGO 牆 | 固定白底，不因背景圖／背景色變化。 |
| LPBN、HBN、IG 等一般曝光版位 | 接收同一組 `bn-color` 色盤；背景圖顯示與文字色盤由上述背景流程同步。 |

## 9. 對匯入工單與維修的傳遞

曝光資源每次廣播色盤時，會把以下資訊傳給外層：

- `mainText`
- `subText`
- `dateText`
- `brandText`

匯入工單與維修在未手動覆寫時，促標底色使用曝光資源的副標色，圓標底色使用曝光資源的主標色，CTA 底色使用曝光資源目前的自動 CTA 底色（主標色）；促標字色使用最新背景色加亮 `50%`。MSBN C／D 的卡片與品名字色另由共用 renderer 的深／淺底規則處理。

## 11. 取色工具 ⇄ BODA ⇄ 曝光資源的文字色同步（2026-11-06）

目標：文字色跟背景色一樣，任一處改了，另外兩處立即跟著變。

**單一輸入、單一算法**

- 自動配色只看「共用背景色」（`wo_shared_canvas_bg_v1`）。嵌在 BODA 時，曝光資源的背景圖也用這個顏色配色，不再用左半邊取樣，因為取色工具與 BODA 只看得到共用背景色。
- 算法以取色工具 `suggest()`／`finish()` 為準；曝光資源 `bnBuildAutoTextPalette()`、`bnAutoCtaBackground()` 與 BODA `colorToolMainTextForBackground()`、`getExposureAutoCtaBg()` 是同一套的移植，結果必須完全相同，改一處要三處一起改。
- 深底主標：三處都是純白。

**同步的欄位**

| 欄位 | 取色工具 → 其他 | 曝光資源 → 其他 | 跟著變 |
| --- | --- | --- | --- |
| 主標 | `wo-color-tool-main-text` | `wo-exposure-color`（mainText） | 品牌名（原本等於主標時）、CTA 底色、圓標底色（自動時） |
| 副標 | `wo-color-tool-sub-text`（含點選其他副標候選） | `wo-exposure-color`（subText） | 日期（原本等於副標時）、促標底色（自動時） |
| CTA 底色／字色（手動） | `wo-color-tool-cta`／`wo-color-tool-cta-text` | `wo-cta-bg`／`wo-cta-text` | — |
| 背景色 | `wo-color-tool-colors` | `wo-bg` | 全部回到自動配色 |

- BODA 推給曝光資源：`_bnApplySharedTextPalette()`（同網域直接呼叫，跨網域送 `wo-shared-text-palette`），會跑禁色／防吃色、重算自動 CTA、存檔、廣播。
- BODA 推給取色工具：`_colorToolSetMainText()`、`_colorToolSetSubText()`；主頁推來的不會再回報。
- 主頁重推「同一個」背景色時（曝光資源第一次載入、匯入工單、還原暫存檔），取色工具不重算，手動色保留，跟曝光資源一致。
- 曝光資源因防吃色／禁色換掉取色工具選的顏色時，取色工具卡片上會顯示「曝光資源的防吃色／禁色規則改用 #xxxxxx」。

**暫存檔配色鎖**（`wo_snapshot_text_palette_lock_v1`）

- 還原暫存檔後，背景色仍是暫存檔那個色時，取色工具的自動建議不會蓋掉暫存檔的主標／副標。
- 只有使用者明確改色（任一處手動改）才會更新鎖；一般廣播不會。
- 使用者換背景色，或在取色工具按「還原建議色」，鎖就清除。

## 12. 驗收清單

- [ ] 深色背景：主／副／日期均為可讀亮色，不再產生近黑文字。
- [ ] 亮黃背景：文字為同系橘／深色，非純黑且可讀。
- [ ] 無背景圖、只換背景色：主／副／日期立即重算。
- [ ] 背景圖右側有明顯主色：左側文字色相可呼應右側視覺。
- [ ] CTA 底色與畫布相近時，自動跳到安全色。
- [ ] CTA 深色底為白字白三角；極淺底為黑字黑三角。
- [ ] 「文字可讀性檢查」四項皆達 `4.5:1`，或明確提示需調整。
