## 4. Active 與實體 schema 邊界

| 類別 | 數量/狀態 | 說明 |
| --- | --- | --- |
| active registry | 107 | `blocks/index.js` 目前主流程載入 |
| subarea active | 72 | 與 `wo-fields` 對應 |
| MSBN active | 35 | 與 `wo-msbn-fields` 對應 |
| 實體 schema | 129 | 目錄裡所有 `block.json` |
| 維護候選 | 由 active ID 推導 | 去掉最後 underscore segment 後嘗試載入 |
| 未 active 範例 | `msbn3p`、base/legacy `subarea_A_1` 等 | 不應直接視為正式上線版位 |

判斷是否上線時，以 `blocks/index.js` 與實際主流程為準；維護頁顯示候選的目的，是讓維護者辨識遺留、重複與可恢復資產。

## 6. 命名與註冊慣例

常見 ID 結構可包含：

- `subarea_…`：主 BOD subarea 家族。
- `msbn_…`：MSBN 類型。
- family/系列/序號/變體段落由現有 registry 決定，不要自行發明與既有 suffix 衝突的命名。

新增資料夾時：

1. 資料夾名與 JSON `id` 一致。
2. `block.json` 中的 refImage 路徑可由 runtime 取得。
3. 需要上線才加入 `blocks/index.js`。
4. 若主頁另有 `manifest.json` 或欄位清單，也要同步檢查。
5. 維護頁、工單、匯出與 QA 都跑一次。

## 7. JBP 與 bottom 資產

### JBP

- `jbp/html/`：17 種 layout 的 HTML/CSS/config CSS。
- `jbp/js/`：runtime、編輯器、state、背景、工單、feedback plugin。
- `jbp/bgimg/`：背景索引與相關資產；plugin 預設期待的 `brand.json` 在本次 checkout 中未找到，需依部署環境確認是否為外部/未提交資產。
- `jbp/fonts/`：JBP 版型字型/字型資產。
- `jbp/banwords.xlsx`：禁用語規則。
- `jbp/firestore.rules`、`jbp/storage.rules`：Firebase 規則檔。

### bottom

- `bottom/src/icons/manifest.js`：產生的 icon library。
- `bottom/tools/build-icon-manifest.js`：manifest 產生工具。
- `bottom/src/templates/`：吸底圖模板。
- `bottom/src/state/projectFile.js`：專案檔格式。
