# 08｜技術規範與視覺渲染規則

文件狀態：依現行 renderer、CSS、渲染設定與既有修正邏輯整理

盤點日期：2026-08-26

## 1. 尺寸與座標基準

### 1.1 主 BOD

- 主組合畫布寬度：1200 px。
- subarea 一般列高：350 px。
- A/B/F 單格常見尺寸：400×350 或 300×350。
- C/D/E 單格常見尺寸：600×350。
- MSBN 大版位：1200×400、1200×430；另有 1200×75 類型。
- schema 座標以設計稿原始像素為基準，預覽時才做 UI scale。

### 1.2 吸底圖

- 輸出：1200×150。
- icon frame、透明留白與白色底區由 `bottom/src/render/canvas.js` 的現行幾何控制。
- viewport scale 不等於輸出尺寸；匯出必須使用 stage 原始尺寸。

### 1.3 JBP

JBP 以各版型 HTML/CSS 自己定義原始尺寸；`layout-runtime.js` 依 iframe DOM 實際尺寸做 fit/zoom/capture。修改 CSS 的一個 subpixel 可能影響瀏覽器預覽與 html2canvas 的輸出差異。

## 2. 字型策略

主 BOD：

- `JS/fonts-embed.js` 提供匯出時的字型 CSS 內嵌能力。
- renderer 的文字位置、line-height、`topExact` 與字型實際 ink top 有關。
- 不應只看 DOM box 的 top 判斷文字視覺位置；需看 raster/參考圖驗證。

吸底圖：

- `FontFace` 載入 Shopee Noto Sans content Medium 500、Bold 700。
- 會用 `document.fonts` 確認載入/ready。
- 字型失敗時目前沒有任意 fallback，避免輸出與設計稿偏離。

JBP：

- 由各 layout CSS 與 runtime 控制。
- 文字量測與 html2canvas baseline 可能與瀏覽器即時排版不同，輸出前需跑現有 clone/capture 修正流程。

## 3. 文字渲染

### 3.1 欄位與限制

文字 field 的內容、最大長度、換行、line-height、對齊、隱藏與 fallback 由 schema 或 layout metadata 決定。新增欄位時應把「輸入限制」與「輸出幾何」視為同一個契約。

### 3.2 精準位置

`topExact`、`designText`、font metrics 與 `tools` 的 ink measurement 是為了處理「字框看似置中、實際字面偏上/偏下」的問題。修正文字時，優先校正文字 ink 與參考圖，不要只調容器 flex alignment。

### 3.3 置中規則

如果需求是畫布或區塊上下左右置中，應區分三個層次：

1. 外層容器是否佔滿可用畫布。
2. 內層內容是否以 flex/grid 或絕對座標置中。
3. 字面 ink 是否因字型 ascender/descender 造成視覺偏移。

JBP/HTML 版型通常需要在 CSS 與 `layout-runtime.js` 的 capture 幾何同時確認；主 BOD schema 則應優先修改 layer 的 metadata/座標。

## 4. 配色規則

### 4.1 對比計算

主 BOD renderer、JBP 背景外掛與 JBP layout runtime 都使用 W3C relative luminance 概念選擇可讀文字。概念流程是：

```text
輸入底色
  → RGB 正規化
  → linearized channel
  → relative luminance
  → 黑/白或 palette 候選對比比較
  → 套用到 role
```

不要用單一 RGB 明暗閾值取代對比計算，尤其背景為照片或飽和色時。

### 4.2 角色關係

| 角色 | 來源/用途 |
| --- | --- |
| `background` | 畫布或版位背景 |
| `mainText` | 主標、主要文字 |
| `subText` | 副標、副文字與目前 CTA 底色來源 |
| `promo` | 促銷、優惠文字或促銷帶 |
| `badge` | 徽章、掛標、badge 底 |
| `cta` | CTA 元件相關顏色 |

### 4.3 CTA 特殊規則

目前明確的 CTA 邏輯：

- CTA 底色跟著副標/副文字角色。
- CTA 文字與三角標針對 CTA 底色選擇反色，使用最大對比的黑或白。
- CTA 三角標不可再獨立吃到 CTA 底色；它與 CTA 文字採一致的 foreground rule。

此規則同時影響 schema renderer 與 JBP 曝光資源配色；修改其中一處時，必須在另一處確認語意是否一致。

## 5. 圖片渲染與吸附

- 圖片 layer 要明確區分 contain、cover、裁切與自訂絕對尺寸。
- `html2canvas` 對 `<img>` 的 `object-fit: contain`、外部圖片、flex 與偽元素處理不完全可靠；JBP runtime 有 clone/canvas 後製邏輯，不能任意移除。
- 主 BOD schema renderer 可用 `imageAbsorb`、`forceImageAbsorb`；個別 schema 可用 `disableImageAbsorb` 排除。
- 下載前最好把外部/blob 圖片轉為 data URL，降低 CORS 或 URL 失效造成的空白圖。
- 圖片的視覺中心不一定等於檔案透明邊界中心；必要時使用 `tools/measure_ref_centers.py`、`measure_ref_ink.py` 等實際量測。

## 6. 匯出一致性

驗收必須同時看：

1. 即時預覽。
2. 單張 PNG。
3. 批次 PNG/ZIP（若該工具支援）。
4. 重新載入快照或專案檔後的預覽。

常見差異來源：字型尚未 ready、瀏覽器與 html2canvas baseline 不同、object-fit 被重算、次像素高度被四捨五入、外部圖片 CORS、clone 樣式漏帶、背景色未套用到匯出節點。

## 7. Icon 視覺規範

主 BOD 目前的導覽與匯入工具列使用線性 SVG：

- `fill: none`
- `stroke: currentColor`
- round linecap/linejoin
- 約 1.75～1.8 px stroke

這個規範只適用 UI icon，不要套到商品/品牌素材或 bottom 的內容 icon。bottom icon 有自己的 library 與 recolor 規則。

## 8. 品質基準

視覺修改後至少要確認：

- 文字 ink top/left 與 reference 的偏差。
- CTA 底、CTA 字、三角標在深色與淺色底上的對比。
- 圖片沒有變形、錯位、被錯誤吸附或被背景裁掉。
- 圓角、clip-path、z-order 與 reference 一致。
- 預覽 scale 改變不影響輸出原始尺寸。
- 外部字型、圖片與背景失效時有可理解的錯誤或 fallback 行為。
