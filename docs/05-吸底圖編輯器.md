## 1. 定位

吸底圖編輯器是可獨立開啟、也可被 BOD 工單生成器嵌入的子工具，專門處理 1200×150 的多 slot banner。它不是主 BOD schema renderer 的另一種 block；它有自己的 state、Konva scene、icon library、專案檔與匯出邏輯。

## 3. State 模型

### 3.1 根 state

```text
state
 ├─ banners: Banner[]
 ├─ activeBannerIndex: number
 ├─ library: CustomIcon[]
 └─ sharpen: boolean
```

初始狀態會建立一個 banner，預設 5 個 slot；slot 數限制為 2～5。

### 3.2 Banner 與 Slot

```text
Banner {
  id,
  activeSlotIndex,
  accentColor: "orange" | "red" | "gray",
  slots: Slot[]
}

Slot {
  id,
  type: "icon",
  text,
  iconId,
  iconText
}
```

`iconText === null` 代表圖片 icon 模式；`iconText` 為字串（包含空字串）代表文字替代模式。兩者與 `iconId` 互斥，修改 UI 時不可只清除其中一個欄位。

### 3.3 Action 類型

目前 action 包括：

`SET_SLOT_COUNT`、`SET_SLOT_TEXT`、`SET_SLOT_ICON`、`SET_SLOT_ICON_TEXT`、`SET_ACTIVE_SLOT`、`COPY_ICONS_TO_ALL`、`COPY_SLOT_ICON_TO_ALL`、`SET_LIBRARY`、`ADD_LIBRARY_ICON`、`SET_ACCENT_COLOR`、`SET_SHARPEN`、`ADD_BANNER`、`REMOVE_BANNER`、`SET_ACTIVE_BANNER`、`SET_BANNERS`。

一般編輯 action 支援 undo/redo；`SET_LIBRARY` 與 `ADD_LIBRARY_ICON` 屬於非 undoable 的 library 更新。

## 4. 渲染與畫布規格

- 輸出尺寸：1200×150。
- Konva 負責 scene graph、事件與 export data URL。
- icon frame：約 107×58；上方保留約 20px 透明區，下方為白色區域。
- 一般 icon 文字：約 22px；文字替代模式約 40px。
- viewport scale：0.25～8。
- Alt+wheel：縮放；一般 wheel：平移；stage 可拖曳。
- `ResizeObserver` 用於響應式調整。

這些是目前程式的基線值，若設計稿變更，應同步更新 canvas、preview、export 與使用說明，不要只改某一個 UI label。

## 5. 色彩與字型

`colorTheme.js` 的 accent：

| key | 色碼 |
| --- | --- |
| `orange` | `#ee4d2d` |
| `red` | `#d0011b` |
| `gray` | `#848484` |

一般 icon 會重新著色；logo 類 icon 啟用時保留原色，未啟用時採 grayscale/coverage mapping。`sharpen` 控制輸出前的銳化選項。

`fontLoader.js` 使用 `FontFace` 載入 Shopee Noto Sans content Medium 500 與 Bold 700：

```text
https://jimmywu-commits.github.io/shopee/fonts/ShopeeNotoSans%28content%29-Medium.ttf
https://jimmywu-commits.github.io/shopee/fonts/ShopeeNotoSans%28content%29-Bold.ttf
```

目前載入失敗會停止繪製/匯出，不會自動換成任意 fallback；這是品質一致性的設計，但也是離線使用風險。

## 6. 專案檔格式

檔案：[`bottom/src/state/projectFile.js`](../bottom/src/state/projectFile.js)

- `FORMAT = "sticky-banner-project"`
- `VERSION = 2`
- 預設檔名：`進度存檔.json`
- v1 單 slot 格式會自動包裝成 v2 banners。
- payload 包含 `format`、`version`、`savedAt`、`activeBannerIndex`、`sharpen`、`banners`、`customIcons`。
- custom icon 會以 data URI 一起保存，確保專案檔可攜。

修改格式時應維持向下讀取策略，並新增 version migration；不要直接改寫既有版本的語意。

## 7. 工單匯入與父頁橋接

`workOrderImporter.js` 會動態載入 SheetJS，解析工作表、辨識版型 header、公開模板代碼與 BODA 吸底圖 metadata，再轉成 editor 可用的 banners。

`parentBridge.js` 的嵌入條件是 `<html class="embed-generator">`。父頁與子頁透過 `postMessage` 傳遞工單 array buffer/file；子頁以 `panelApi.importWorkOrder` 接手。

因此修改主 BOD 的「sticky」分頁時，必須同時測試：

1. 獨立開啟 bottom/index.html。
2. `?embed=generator` 嵌入狀態。
3. 主頁送出工單後的接收。
4. 子工具 state 與匯出是否仍獨立。

## 8. 匯出流程

`ExportBatch` 會逐 banner/組合產生 PNG，顯示進度，必要時以 JSZip 打包。匯出前需確認字型 ready、圖片 data URL 可讀、Konva stage 尺寸正確、active/非 active 狀態符合設計。

## 9. 既有已知風險

- icon manifest 是產生物，不能把手動修改當成永久來源。
- script order 取代了 module dependency，新增檔案要放在正確載入位置。
- `panel.js` 偏大型，修改時要避免把 state 邏輯與 render/UI 進一步混在一起。
- 沒有自動化單元測試或瀏覽器回歸測試。
- 依賴外部字型/CDN；直接雙擊 HTML 可能遇到載入或 CORS 問題。
